# Qua Native Renderer

Use this skill for `packages/native/*`, Rust native runtime/renderer crates, native host contracts, native asset/store adapters, QUI/QSS native authoring, and native packaging.

## Boundaries

- Native renderer is a projection layer only.
- Engine/store remain authoritative for game state, save/load, settings, audio intent, UI overlays, runtime packages, and plugin state.
- Communication uses `@quajs/pipeline` and render-core/plugin projections; do not add a second event bus.
- Runtime content remains Quack-built QPK packages. Dynamic QPKs may contain QS/JS modules and resources only, never native code.
- Native runtime package guards must scan script/plugin/scene/migration asset references, their runtime module variants, plus emitted bundle asset names, paths, relative paths, and variant names/paths for empty or suffix-only names, absolute/remote/traversal references, and forbidden native payload extensions before QuickJS evaluation. They must also reject package-level and plugin-level native-code declarations such as `nativeBinaries`, `nativePayloads`, `nativeEntry`, or truthy `nativeCode`, not only compatibility metadata. Package-level and plugin-level native renderer compatibility blocks (`metadata.nativeRenderer` and `metadata.renderers.native`) must explicitly declare `nativeCode: false`; missing or truthy values are blockers before signature verification.
- Native version/capability data comes from the signed native app/Rust build and is exposed through `QuaNativeHostInfo`; QPK content cannot override it.
- Rust native startup must fill `QuaNativeHostInfo.runtime.quickjsVersion` from `quickjs_runtime_version()`. Builds without an installed QuickJS evaluator report `unsupported`; do not leave the startup host info at `pending` or claim a real QuickJS engine version before a backend exists.
- Native runtime package compatibility may be declared as `metadata.nativeRenderer` or target-scoped `metadata.renderers.native`; checks normalize `renderer`/`rendererPackage` to `packageName`, `version`/`rendererVersion` to `versionRange`, and `capabilityIds`/`optionalCapabilityIds` to capability requirement lists before activation. Required `assetKinds`, `qssFeatures`, and `quiComponents` must be checked against host renderer capabilities before activation; optional asset kinds, optional QSS features, and optional QUI components may warn and fall back without blocking activation. Native compatibility blocks must explicitly declare `nativeCode: false`; missing or truthy values are rejected before signature verification or script evaluation. Dynamic UI package builders and third-party native renderer entries should use `createNativeUiSurfaceCompatibility` or `@quajs/native-ui-compiler`'s `createNativeUiSurfaceCompatibilityFromDocuments` so `native-wgpu.ui.surface@1`, `qui` / `qss` / `tokens`, renderer package metadata, document-derived QSS features / QUI components / asset kinds, and `nativeCode: false` stay consistent with the actual renderer capability manifest without inventing undeclared audio/video capabilities.
- Native dynamic module loading must use `createNativeRuntimeModuleLoader` or an equivalent restricted loader. It may load only runtime-package-declared, package-relative JavaScript module-like `assetName` script assets (`.js`, `.mjs`, or `.cjs`) through QuaAssets/native host bytes, then pass code to a trusted Rust/QuickJS evaluator. The loader itself must also reject unsafe runtime module variant asset/module references and native payload-looking extensions as defense in depth, even though trust policy guards run before activation. Do not load runtime modules from filesystem paths, URLs, Node resolution, Web `Blob`, or dynamic `import()`.
- Rust `quajs_native_runtime` QuickJS request validation must mirror the restricted TS loader and shared contracts helper: package-relative asset names only, JavaScript module-like extensions only (`.js`, `.mjs`, `.cjs`) after stripping inert `?query` / `#hash` suffixes, explicit native-payload rejection after stripping the same suffixes, module bytes and UTF-8 code bytes capped by `maxModuleBytes`, and no filesystem/URL/native payload escape hatches before evaluator dispatch.
- `@quajs/native-contracts` owns `validateNativeQuickJsEvaluationRequest` / `assertNativeQuickJsEvaluationRequest` for the shared QuickJS wire boundary. `@quajs/engine-native` must call this assertion immediately before `host.evaluateQuickJsModule`, so manually constructed evaluation requests are blocked before reaching Rust even when they bypass the higher-level runtime module loader.
- When using the native host QuickJS bridge, `moduleNamespaceId` is only an opaque Rust/QuickJS namespace handle. `@quajs/engine-native` must use an explicit namespace resolver before returning a real engine module namespace object; do not fake module exports from the id string.
- Native host QuickJS cleanup APIs (`releaseQuickJsModuleNamespace`, `releaseQuickJsPackageNamespaces`, `getQuickJsNamespaceSummary`, and `getQuickJsPackageNamespaceSummary`) are resource-ledger APIs only. Real hosts must use a persistent `QuickJsModuleNamespaceRegistry` across evaluation/release calls, not a per-request temporary registry, so runtime package unload can release package-owned namespace handles and check memory summaries.
- `@quajs/engine-native` must release package-owned QuickJS namespaces from the late renderer-facing runtime-package unload event (`LogicToRenderEvents.RUNTIME_PACKAGE_UNLOAD`), after runtime engine plugins have been unloaded. It should call `releaseQuickJsPackageNamespaces(packageId)` when the host supports it, so successful QuickJS namespace handles do not outlive their owning Runtime QPK without being released before plugin teardown. Cleanup failures must be recorded and reported as recoverable `render/error` events with phase `quickjs-cleanup`; they must not block or rethrow from the runtime-package unload pipeline.
- Rust `quajs_wgpu_renderer` consumes resolved QUI/QSS projection data only. QSS parsing, selector matching, cascade, inheritance, and language-server diagnostics belong in TS/compiler/tooling packages, not in the renderer.
- Rust `quajs_wgpu_renderer` projection DTOs serialize/deserialize the native bridge JSON boundary with camelCase fields. Native UI surface node `kind` values must stay aligned with QUI registry component names such as `Box`, `Text`, and `Button`; do not add Rust-side parsing of QUI/QSS authoring syntax to make up for malformed projection JSON.
- Rust `quajs_wgpu_renderer` exposes `NativeRendererJsonFrameInput` and JSON facade methods for native app / QuickJS bridge ingestion of already-resolved layout, container, and view projection data. These helpers may deserialize camelCase bridge JSON and call existing frame preparation/rendering paths, but they must not parse QUI/QSS authoring syntax or become renderer-owned game state.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe native bridge stage inputs before frame preparation. Validate `NativeRendererJsonFrameInput.layout` and `.container` fields for finite positive dimensions, finite positive bounded aspect ratios, non-inverted aspect intervals, finite positive bounded `devicePixelRatio`, and finite non-negative bounded safe-area insets. The lower-level stage layout resolver may normalize internal caller values, but the JSON bridge must fail malformed app / QuickJS input instead of silently falling back.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe package asset references before frame preparation, backend submission, or audio planning. Validate known projection `assetName` fields and declarative UI surface `key` fields for empty or suffix-only names, URLs/URI schemes, absolute paths, backslash paths, traversal, and native payload-looking extensions after stripping `?query` / `#hash` suffixes. Validate known projection `assetType` fields as safe native asset-kind identifiers so resolved JSON cannot inject paths, URL schemes, or empty resource namespaces into renderer resource IDs. Validate resolved dialogue/UI `fontFamily` names because they become `fonts:*` resource ids; they may contain normal font-name spaces but must not be empty, URL/scheme-like, path-like, traversal-like, query/hash-suffixed, namespace-separated with `:`, control-character-bearing, or native payload-looking. Validate resolved dialogue/UI color fields (`RichTextStyle.color`, `UiSurfaceResolvedStyle.backgroundColor`, `borderColor`, and `color`) as safe native color literals only: hex, `rgb(...)`, `rgba(...)`, `transparent`, `currentColor`, or basic named colors. Rust should defensively reject malformed resolved JSON, but it must not parse QSS or infer fallback meaning for invalid color syntax.
- Rust `quajs_wgpu_renderer` JSON facade must also reject unsafe package provenance ids before frame preparation, because `contentPackageId` and `requiredRuntimePackages` flow into draw commands, resource ownership, memory metrics, and package unload blockers. Validate known projection provenance fields for empty/whitespace ids, URL/URI schemes, absolute/path-like ids, traversal markers, query/hash suffixes, control characters, and non-identifier characters; Rust should reject malformed resolved JSON rather than letting unsafe package ids pollute renderer ledgers.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe non-UI projection identity fields before frame preparation. Validate background layer `id`, character `id`, choice `id`, and audio track `id` with the same safe native identifier rules used for UI dispatch identifiers, and require each of those ids to be unique within its owning frame scope. These ids become draw command ids, renderer intents, resource ids, audio backend track ids, or memory/resource ledger identities.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved UI dispatch identifiers before frame preparation. Validate overlay `elementId`, overlay `overlayStack`, scene shell `overlay.overlayStack`, UI scene `id`, UI surface node `id`, intent `action`, canonical `choiceId`, and UI intent metadata keys for empty values, surrounding whitespace, control characters, dangerous URL/native/shell/FFI-like URI schemes, query/hash suffixes, absolute/path-like values, traversal markers, native payload-looking suffixes, and unsafe characters. Overlay `elementId` values must be unique within a frame's UI overlay list, UI scene `id` values must be unique within a frame's UI scene list, and UI surface node `id` values must be unique within each resolved surface tree, because these fields become draw command ids, hit-test element ids, scene/surface identities, overlay grouping/sort keys, or renderer intent dispatch payloads. Malformed resolved JSON must fail before command graph construction.
- Rust `quajs_wgpu_renderer` JSON facade must cap resolved UI intent metadata before frame preparation because it is copied into native host `NativeRendererIntent.payloadJson`. Metadata keys must pass the safe dispatch identifier rules, and metadata payloads must stay within native renderer limits for entry count, total estimated bytes, string bytes, array/object fanout, and nesting depth. This is only a resolved payload guard; Rust must not parse business-specific action semantics or mutate engine state from metadata.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved UI geometry before frame preparation. Validate `UiSurfaceNodeProjection.bounds` coordinates and scroll offsets as finite logical values within native renderer limits, and validate `bounds.width` / `bounds.height` as finite, non-negative logical dimensions within those limits. This is a resolved-projection guard only; it must not add Rust-side QUI/QSS layout parsing or renderer-owned layout state.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved UI style numbers before frame preparation. Validate node `opacity`, style `opacity`, `backgroundPosition`, `borderRadius`, `borderWidth`, `fontSize`, `letterSpacing`, `lineHeight`, and `padding` as finite values inside the native renderer limits, with opacity/background positions normalized to `0..=1` and logical style values non-negative. Rust must reject malformed resolved JSON rather than silently clamping or reinterpreting QSS semantics.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved UI text payloads before frame preparation. Validate `UiSurfaceNodeProjection.text` for native renderer text payload limits and unsupported control characters before it enters button/text draw params or future glyph layout. This is a resolved bridge guard only; QUI content-model validation, localization policy, text interpolation, and rich text authoring semantics remain in TS compiler/tooling.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved dialogue/rich-text payloads before frame preparation. Validate plain dialogue text, speaker text, rich-text span text, and the aggregate `rich_text_to_plain_text` byte length for native renderer text payload limits and unsupported control characters before they enter `TextDrawParams` or future glyph layout. This is a resolved bridge guard only; dialogue authoring policy, localization, interpolation, and rich-text syntax semantics remain in engine/compiler/tooling.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved z-order values before frame preparation. Validate background layer `zIndex`, character `layer`, UI overlay / scene overlay `stackPriority` and `zIndex`, and UI surface node `zIndex` against native renderer limits before they enter overlay sorting, render graph z ordering, hit testing, or command generation. Internal render graph sorting should still use saturating arithmetic as defense in depth, but malformed bridge JSON must fail instead of relying on saturation.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved dialogue/rich-text numbers before frame preparation. Validate `RichTextStyle.fontSize` and `lineHeight` on speaker style, document style, and span style as finite positive logical values inside native renderer limits. These values become text draw parameters and font resource planning context, so malformed resolved projection must fail before command construction rather than falling back to default typography.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved background/video numbers and origins before frame preparation. Validate background and layer `x` / `y`, optional `width` / `height`, `scale`, `rotation`, and `opacity`, plus video projection `opacity`, as finite values inside native renderer limits; dimensions must be non-negative, scale must be greater than 0, rotation must be finite and bounded, and opacity must be normalized to `0..=1`. Validate background, layer, and video `origin` strings as resolved native origin values only: `left|center|right`, `top|center|bottom`, or `0%..100%` percentage axes in one-axis or two-axis form. URL, path, traversal, URI-scheme, empty, overlong, control-character, or out-of-range percentage origins must fail before command construction. This is a resolved projection guard for background layout, image/layer transform projection, and video poster/fallback projection only; it must not parse QSS, silently clamp malformed projection values, or declare real video decode support.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved character numbers before frame preparation. Validate character position `x` / `y`, `xPercent` / `yPercent`, optional `width` / `height`, `scale`, `rotation`, and character `opacity` as finite values inside native renderer limits; dimensions must be non-negative, scale must be greater than 0, and opacity must be normalized to `0..=1`. This is a resolved projection guard for character draw command planning only; Rust must not silently fall back from malformed character projection values that should have been rejected by tooling or engine projection.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved audio numbers before frame preparation. Validate audio track `volume` as a finite normalized `0..=1` value and audio track memory estimate fields (`bufferCpuBytes`, `streamCpuBytes`, `handleCpuBytes`) against native renderer limits before they enter backend command planning, memory metrics, or package unload blockers. This is still renderer-local projection/resource validation, not a real audio playback capability declaration.
- Rust `quajs_native_app` may use `QUA_NATIVE_RENDERER_SMOKE_FRAME` to read an already-resolved projection JSON fixture and submit it through `NativeRendererJsonFrameInput` plus `NullNativeRenderBackend` as a debug/CI smoke check. It should emit both a human-readable summary and a machine-readable `Qua native renderer smoke json: ...` line with missing-resource, fallback, declarative resource, total memory, memory-by-kind, memory-by-package, declarative package memory, audio package memory, audio resource, and active audio track metrics. When `QUA_NATIVE_RENDERER_SMOKE_BUDGET` points to a JSON budget file, startup should fail if any smoke metric exceeds its configured max, including total memory, resource-kind memory, package owned/dependent memory, declarative package memory, and audio package memory; CLI smoke tests must cover both passing and failing kind/package/declarative/audio package budget maps. This hook and budget gate must not load QUI/QSS authoring files, ordinary plugins, Web/Cocos/native target core bootstrap arrays, Runtime QPK executable dependencies, or any native payloads.

## Package Responsibilities

- `@quajs/native-contracts`: serializable native host, renderer capability, compatibility, QUI/QSS, and target bootstrap contracts. Packagers should use `createTargetCoreSelection` to derive the active Web/Cocos/native resolver identity, core family, and selected adapters from one target value; native packagers should use `createNativeCapabilityManifestPayload` / `createNativeCapabilityManifestHash` with an injected SHA-256 implementation when emitting `nativeRenderer.capabilityManifestHash`; use `createTargetBundleNativeRendererInfo` to derive native target-bundle renderer metadata from the actual renderer capabilities. Keep `@quajs/native-contracts` platform-neutral and covered by source-level import isolation tests so shared validation code does not import Web, Cocos, or native runtime adapter packages.
- `@quajs/engine-native`: engine plugin/adapter that reads native host info, registers renderer capabilities, supplies runtime package compatibility guards, and exposes the restricted native `RuntimeModuleLoader` over package asset bytes plus a Rust/QuickJS evaluator.
- `@quajs/engine-native` also owns the native renderer intent bridge. It installs a host-side `emitRendererIntent` callback during plugin initialization, parses Rust `NativeRendererIntent` payloads, emits `choice/select` as `RenderToLogicEvents.USER_CHOICE_SELECT`, emits `ui/intent` as a generic render-to-logic UI intent, and forwards `open` / `close` / `update` actions to the existing UI overlay request events without creating a second event bus.
- `@quajs/assets-native`: QuaAssets adapter over native host byte/storage/crypto APIs.
- Native asset hosts should provide `listStorageKeys` when cache roots need full cleanup; `@quajs/assets-native` may fall back to index-known asset deletion when key listing is unavailable, but full orphan cleanup requires host prefix listing.
- `@quajs/store-native`: QuaStore persistence adapter over native host storage APIs.
- Native store hosts must provide `listStorageKeys` when using list or prefix-clear save operations; missing key listing support must fail explicitly instead of making snapshots/save slots appear empty.
- `@quajs/native-ui-compiler`: native QUI/QSS authoring compiler for parse, validation, formatting, completions, hover metadata, component registry, QSS feature registry, static QUI/QSS surface projection compilation, projection requirement collection via `collectNativeUiSurfaceProjectionRequirements`, and native UI surface compatibility metadata via `createNativeUiSurfaceCompatibilityFromDocuments` / `createNativeUiSurfaceCompatibilityFromProjection`. Projection requirement collection must distinguish resolved projection fields (`visible`, `opacity`, `scrollOffsetX`, `scrollOffsetY`, `provenance`, etc.) from QSS feature names so runtime compatibility metadata does not confuse compiler-only projection shape with QSS declaration support. It may depend on platform-neutral contracts only and must not import Web, Cocos, or native runtime bootstrap adapters.
- `@quajs/native-language-server`: standalone `.qui/.qss` LSP adapter, in-memory project index, document-link helpers, component/class/id definition, reference, and rename edit queries, QUI/QSS package-relative asset reference indexing for `Image(src|image)` and QSS `asset(...)`, LSP definition/documentLink/references/rename providers, missing asset diagnostics, asset quick fixes, and a package bin that defaults to stdio when no transport argument is supplied. The pure project index should only create candidate links; the LSP server may resolve existing `file://` candidates with a read-only file-exists check for unopened resources and emit `NATIVE_UI_ASSET_MISSING` warnings for unresolved asset candidates. Asset quick fixes may remove missing/invalid resource references through `quickfix` / `source.fixAll.quaNativeAssets`, but must not create files, scan workspaces, load resources, or trigger target runtime/bootstrap code. It is an authoring tool only; it must not load Web/Cocos/native target core bootstrap plugins, ordinary game plugin arrays, or runtime QPK executable dependencies.
- `packages/native/vscode` (`qua-native-authoring` VSCode extension): standalone editor extension for native `.qui/.qss` files. It should start the native LSP, contribute language ids `qua-ui` and `qua-style`, expose commands for format, validation, restart, and applying the LSP `source.fixAll.quaNativeAssets` action to the active native UI document, and avoid importing `@quajs/renderer-web`, `@quajs/renderer-cocos`, or native app/runtime bootstrap packages. Keep a source-level import isolation test in this package so extension tooling cannot accidentally import Web, Cocos, or native runtime/bootstrap packages.
- `@quajs/native-benchmarks`: deterministic native authoring/tooling smoke benchmarks. It measures QUI/QSS parse+validate, QSS style resolution, static surface projection compilation, resolved-projection requirement collection, projection-derived native UI surface compatibility metadata, format, completion, hover, native asset code action/fixAll generation, project index build/incremental update, document-link/reference counts, document size, diagnostics, elapsed time, and process memory deltas through `@quajs/native-ui-compiler` and `@quajs/native-language-server` public APIs only. It must not start a renderer, load Web/Cocos/native target core bootstrap adapters, parse ordinary game plugin arrays, access the network, or use randomized fixtures. Keep a source-level import isolation test in this package so benchmark and acceptance tooling cannot accidentally import Web, Cocos, or native bootstrap core packages.
- Rust `quajs_native_runtime`: QuickJS host and native host API implementation.
- Rust `quajs_wgpu_renderer`: wgpu projection renderer and transient resource management.

## Target Isolation

Web, Cocos, and native target core adapters must not be mixed:

- Web uses Web assets/renderer/framework adapters only.
- Cocos uses Cocos host/renderer only.
- Native uses `@quajs/engine-native`, `@quajs/assets-native`, `@quajs/store-native`, and Rust native runtime/renderer metadata only.
- Web, Cocos, and native core bootstrap plugins are target roots, not ordinary game plugins. They must not be placed in one shared plugin array, umbrella preset, Runtime QPK executable dependency list, or runtime resolver path that imports every target and chooses one later.
- Web, Cocos, and native packaging must use separate target-core resolver contexts. Shared validation schemas are fine, but a shared all-target core plugin list is invalid even if later filtering appears to remove inactive entries.
- Packaging to Web, Cocos, or native must begin from the active target resolver. Do not build `[webCore, cocosCore, nativeCore]` or any shared all-target bootstrap preset and filter afterward; inactive target core plugins must not be imported, registered, bundled, or kept as executable QPK dependencies.
- `@quajs/native-contracts` may be used by Web/Cocos build tooling for target validation, but it must not remain in Web/Cocos runtime bundles after tree-shaking.
- Target selection must happen before bootstrap/plugin resolution. Do not build an umbrella app that imports Web, Cocos, and native core plugins and chooses one at runtime.
- Core target plugins are reserved bootstrap infrastructure, not normal game plugins. Do not put Web/Cocos/native bootstrap adapters in ordinary plugin arrays, shared presets, Runtime QPK executable dependencies, or generated plugin resolver paths.
- Quack/native packaging should materialize one read-only `TargetCoreSelection` for `web`, `cocos`, or `native` before resolving normal engine/game plugins. Shared plugin resolution may consume that selection but must not add another target core family. The emitted `target-bundle-manifest.json` must record the matching resolver identity as `targetCoreResolver`: `web-core-resolver`, `cocos-core-resolver`, or `native-core-resolver`.
- Packaging a Web, Cocos, or native project must select exactly one target bootstrap. Target-specific renderer plugin entries and core adapters are not interchangeable between targets.
- Web, Cocos, and native project templates/starters are target-specific shells. Web starters may consume only the Web target-core resolver, Cocos starters only the Cocos target-core resolver, and native starters only the native target-core resolver; debug shells, smoke runners, installers, and updaters must consume the emitted active-target `target-bundle-manifest.json` rather than importing or re-declaring any target core adapter.
- When generating Cocos, Web, or native projects, target core plugin wiring must happen only in that target's packager resolver. Project templates, generated startup code, debug/release shells, installers, updaters, and smoke runners must never carry another target's core plugin and filter it later.
- Packaging to Cocos, Web, and native projects must keep target core plugins out of ordinary project templates entirely. A template, starter, debug shell, installer, updater, smoke runner, or runtime package that imports multiple core families and then filters by target is a release-blocking target-core leak even when the final emitted manifest appears single-target.
- Treat the three target bootstrap plugin families as disjoint: `web-core`, `cocos-core`, and `native-core`. Every packaged artifact must record exactly one selected family, and `target`, selected core adapters, renderer entries, and Runtime QPK executable dependencies must all agree with that family.
- Treat target core plugins as release-blocking isolation boundaries. Web artifacts must exclude Cocos/native core adapters, Cocos artifacts must exclude Web/native core adapters, and native artifacts must exclude Web/Cocos core adapters after bundling/tree-shaking, not just in source metadata.
- Shared engine/game/plugin code may be reused across targets only through platform-neutral entries. Shared entries must not eagerly import `@quajs/renderer-web`, `@quajs/renderer-cocos`, `@quajs/engine-native`, `@quajs/assets-native`, `@quajs/store-native`, Cocos host adapters, or native runtime adapters.
- Validate target isolation at three layers: application bootstrap core adapters, target-specific renderer/plugin entries, and Runtime QPK renderer compatibility metadata. Do not let a pass in one layer imply the others are safe.
- Use `validateExclusiveTargetBootstrap` from `@quajs/native-contracts` to assert a packaged app/startup dependency set registers exactly one Web, Cocos, or native bootstrap. Then use `validateTargetBootstrap` for the active target and treat both `missing` required target adapters and `forbidden` cross-target adapters as blockers.
- Use `validateOrdinaryPluginListTargetIsolation` from `@quajs/native-contracts` before ordinary game/plugin resolution. Quack packagers should call `assertQuackPluginReferencesTargetIsolation` / `assertLoadedQuackPluginTargetIsolation` at CLI, config, generated resolver, and loaded-plugin boundaries. Any Web, Cocos, or native target core root or subentry in `plugins`, shared presets, or generated plugin resolver paths is a blocker; target bootstrap must come only from the active target-core resolver. When ordinary plugin references include both `specifier` and `packageName`, both fields must be normalized and checked so a safe-looking package name cannot hide a target core subentry in the specifier, or vice versa.
- Use `validateTargetPluginManifest` from `@quajs/native-contracts` for third-party and official plugin source metadata before bundle entry selection. Plugin entry `target` metadata must be one of `shared`, `web`, `cocos`, or `native`; shared plugin entries must import no target core adapters, selected entries must match the active target, inactive target entries must not be eager, and target entries may import only their own target adapters plus shared logic.
- Inactive eager plugin entries must also report any Web/Cocos/native core adapter imports they would pull into the active artifact, so packagers can reject and locate target-core leakage before bundling.
- Use `validateTargetBundleManifest` from `@quajs/native-contracts` for emitted `target-bundle-manifest.json` files. Pass `expectedTarget` from the packaging/runtime context so a manifest declared for Web, Cocos, or native cannot be silently reused by another target. When `expectedTarget` is present, resolver, selected core plugin family, selected core adapters, renderer entry targets, runtime package target-core guards, artifact metadata, and native renderer metadata must all be checked against that packaging/runtime context target rather than trusting the manifest's self-declared target. It validates `targetCoreResolver`, the explicit selected core adapter set, normalized runtime dependencies, selected renderer entry targets, Runtime QPK renderer entry targets, Runtime QPK executable dependencies, `projectGraphs`, and target-scoped native renderer metadata together after bundling/tree-shaking.
- Emitted target bundle manifests may use `projectGraphs` to record project-template, startup-shell, debug-shell, release-shell, smoke-runner, installer, updater, dev-server, post-bundle, or custom dependency graphs. Non-`post-bundle` graphs must remain platform-neutral and must not declare any Web/Cocos/native target core adapter, including the active target family; `post-bundle` graphs may contain the active core family but must still reject inactive target core roots or subentries. This lets templates and shells prove they consume the active target manifest instead of re-declaring bootstrap plugins.
- Native target bundle validation must reject missing, empty, or invalid artifact metadata required by packaging and startup, including `profile` (`debug`/`release`) and native `platform` (`macos`/`windows`/`linux`).
- Native target bundle validation must reject missing or empty release app metadata required by packaging and startup, including `app.bundleId`, `app.version`, `app.buildNumber`, and `app.icon`.
- Native project packaging metadata should come from the unified Qua project manifest `targets.native`, including `platforms`, `profiles`, `outputDir`, `app.bundleId`, `app.version`, `app.buildNumber`, `app.icon`, native asset target, and build options.
- Quack native packaging should consume `createQuaProjectNativeArtifactPlans` so debug/release outputs are isolated by `outputDir/profile/version-buildNumber/platform` before target-bundle manifests, signing, or distribution artifacts are written.
- Quack packagers should use `emitQuaTargetBundleManifest` to validate and write Web, Cocos, and native `target-bundle-manifest.json` files with the active `expectedTarget`. Native packaging should use `emitQuaProjectNativeTargetBundleManifest` as the native artifact-plan wrapper around the shared emitter.
- Quack/native packaging must emit a post-bundle `target-bundle-manifest.json` for every Web, Cocos, and native debug/release artifact. Native target manifests created by `createQuaProjectNativeTargetBundleManifest` automatically append a `native.<profile>.<platform>.post-bundle` `projectGraphs` record from dependencies, renderer entries, and Runtime QPK executable/renderer references; callers may pass additional template/startup/installer/updater/smoke graphs, which must stay platform-neutral. Validate the emitted manifest after tree-shaking, not just the source dependency set.
- Runtime startup must repeat the exclusive-target assertion before engine initialization so hand-built shells cannot register zero or multiple target core adapter sets. Native startup should use `createNativeEngineBootstrap` and pass the emitted `target-bundle-manifest.json` into its `targetBundleManifest` option when available, falling back to `targetBootstrapPackages` only for lightweight tests or hand-built debug shells. After reading host info, `@quajs/engine-native` must verify emitted app identity/profile/platform metadata plus native renderer package/version/backend/declared backendVersion/capability ids and capability manifest hash against the actual Rust host info before exposing the plugin as initialized.
- Rust `quajs_native_app` startup must validate native `target-bundle-manifest.json` data before building `NativeHostInfo` or starting QuickJS/engine. It can load the emitted manifest from `QUA_NATIVE_TARGET_BUNDLE_MANIFEST` and should reject unreadable/invalid manifest files, invalid artifact `profile`/`platform` values, mismatched or missing `targetCoreResolver`, missing or empty app metadata (`app.bundleId`, `app.version`, `app.buildNumber`, `app.icon`), app identity/profile/platform mismatches, missing or invalid `nativeRenderer` package/version/backend/capability metadata, foreign Web/Cocos core roots, non-native renderer entry targets, Runtime QPK target-core executable/renderer entries, and `projectGraphs` that either declare any target core outside `post-bundle` or include inactive Web/Cocos core adapters in `post-bundle` before host-info construction. Startup dependency normalization must handle bare package specifiers, `?query` / `#hash` bundler suffixes, Windows/backslash paths, `node_modules` paths, and pnpm `.pnpm` store paths before deciding whether a dependency is Web/Cocos/native core. After constructing host info, it must compare emitted renderer package/version/backend/declared backendVersion/capability ids and capability manifest hash against the actual Rust host info before QuickJS or engine startup.
- Validate package subentries by normalized package root; for example `@quajs/renderer-web/plugins/audio` is still Web core, and must not appear in native/Cocos bundles.
- Validate both `specifier` and `packageName` fields on target bundle references, plugin import references, and Runtime QPK executable/renderer references. Normalize bare subentries, `npm:` specifiers, `?query` / `#hash` suffixes, Windows/backslash paths, `node_modules` paths, and pnpm `.pnpm` store paths to package roots before target-core classification. A safe-looking `packageName` must not mask a Web, Cocos, or native target-core subentry/path in `specifier`, or vice versa.
- Shared plugin entries must not import Web, Cocos, or native core adapters. Target entries may import only their own target adapters plus platform-neutral shared logic.
- Multi-target plugin packages may declare Web, Cocos, and native entries in source metadata, but packaging must include only the active target entry and reject accidental imports of inactive target entries.
- Renderer entry records in emitted target bundle manifests must explicitly declare their target. A Web/Cocos/native artifact must fail validation if an app renderer entry or Runtime QPK renderer entry omits target metadata or declares another target, even when the entry comes from a third-party plugin package rather than an official core adapter package.
- Runtime QPKs may declare compatibility with Web, Cocos, and native, but inactive target blocks are metadata only. They must not carry executable dependencies on target core adapters, install target bootstrap plugins, or activate another target bootstrap.
- Runtime package guard must reject `executableDependencies` and `rendererEntries` that normalize to any Web, Cocos, or native target core adapter root, including target subentries such as `@quajs/renderer-web/plugins/audio`, `@quajs/renderer-cocos/plugins/dialogue`, or `@quajs/engine-native/runtime`.
- Dynamic QPK activation must evaluate only the active artifact target block. A Web build ignores native/Cocos compatibility blocks, a Cocos build ignores Web/native blocks, and a native build ignores Web/Cocos blocks while still rejecting native-code payloads for native.
- Every packaged debug/release artifact should emit a target bundle manifest and run dependency graph checks so Web builds exclude Cocos/native core adapters, Cocos builds exclude Web/native core adapters, and native builds exclude Web/Cocos core adapters.
- Runtime startup should assert exactly one target adapter set registered with the engine, so hand-built bundles cannot mix Web, Cocos, and native core plugins.
- Implement target core plugin resolution in this order: normalize target, select exactly one bootstrap preset, materialize that target's adapters/renderer/host bridge, resolve shared engine/game plugins, select active third-party target entries, bundle/tree-shake, emit `target-bundle-manifest.json`, validate it, then assert it again at runtime startup.
- Implement target core plugin resolution through target-specific functions or contexts such as Web-only, Cocos-only, and native-only resolvers. Do not let debug/release/updater/installer paths bypass the same emitted manifest validation.
- Do not introduce all-target core helpers such as `resolveAllTargetCore()`, `createCorePluginsForAllTargets()`, umbrella target core presets, or barrel exports that import Web, Cocos, and native bootstrap adapters before filtering. Target-specific resolvers may share schema and metadata helpers only when those helpers do not import inactive target bootstrap entries.
- Treat target isolation CI as two mandatory layers: a contracts suite with symmetric Web/Cocos/native fixtures for bootstrap, ordinary plugin, plugin manifest, and target bundle validation; and a packager suite that proves debug, release, installer, updater, hand-built shell, and post-bundle dependency graph paths all call the same isolation helpers. Include a negative fixture where code first constructs the Web/Cocos/native core plugin union and filters afterward; it must fail even if the final manifest appears single-target.
- Run the same source selection, renderer entry, post-bundle graph, runtime startup, and Runtime QPK gates for all three targets. Native cannot be the only strict path; Web and Cocos builds must reject native core adapters with the same severity that native builds reject Web/Cocos adapters.
- Test target isolation symmetrically. Web fixtures must reject Cocos/native leakage, Cocos fixtures must reject Web/native leakage, and native fixtures must reject Web/Cocos leakage. Native-only rejection tests are not enough.
- When packaging Web, Cocos, or Native projects, treat core bootstrap plugins as mutually exclusive roots at every layer: bootstrap selection, ordinary plugin lists, shared presets, third-party target entries, renderer entries, Runtime QPK executable dependencies, post-bundle dependency graphs, emitted manifests, installer/updater artifacts, and runtime startup. A dependency hidden in either `specifier` or `packageName` is still leakage.

Shared engine/game/plugin packages may be reused only when platform-neutral.

## QUI/QSS Projection

- Inline QUI surface nodes are renderer projections, not authoritative UI state.
- Supported foundational QUI node kinds are `Fragment`, `Box`, `Stack`, `Row`, `Column`, `Grid`, `Backdrop`, `Button`, `Divider`, `Layer`, `SafeArea`, `Spacer`, `Text`, `RichText`, `Image`, `Panel`, and `Scroll`; higher-level components such as dialog, drawer, save/load panels, gallery, and settings should compose from these base nodes.
- QUI authoring supports declarative conditional and loop directives in compiler/tooling only. `else-if` / `else` branches must be adjacent to an active conditional chain, duplicate directives on one node are invalid, `for` supports `item in source` and `(item, index) in source`, and loop-rendered nodes must declare a stable `key` so native renderers never infer list identity.
- `@quajs/native-ui-compiler` must normalize QUI `action:` values through shared action descriptors before projection. `ui.*` emits `ui/intent` with the method as `action`, `choice.select(choiceId)` emits `choice/select`, and `save.*` / `settings.*` stay declarative `ui/intent` actions with namespaced action names. Do not re-parse action strings in LSP, projection compiler, or Rust renderer paths.
- Native UI `choice/select` intents must carry canonical `choiceId` on the resolved intent projection, not only inside arbitrary metadata. Rust JSON facade must reject `choice/select` UI surface intents without canonical `choiceId`; native intent serialization must let canonical `choiceId`, `action`, and `elementId` overwrite same-named metadata fields so dynamic UI content cannot forge dispatch identity. Rust JSON facade must also reject unsafe or oversized UI intent metadata before that metadata can become native host `payloadJson`.
- `@quajs/native-ui-compiler` exposes `NativeQuiDocument.tree` and `parseQuiStructureTree` as the shared authoring AST for projection compiler and LSP features; Rust native renderer must not parse QUI or QSS authoring syntax.
- QUI component registry entries must declare a content model (`children`, `text`, or `none`). Compiler/LSP diagnostics should reject nested QUI components inside `Text`/`RichText`, child content inside no-content leaves such as `Image`/`Divider`/`Spacer`, orphaned named slots, unknown parent slots, and duplicate slot blocks before Rust receives a projection tree.
- Native QUI hover metadata should come from the same component registry and expose content model, slots, and style parts instead of duplicating component documentation in the VSCode extension.
- `Fragment` is a command-free structural grouping node. It expands its children in place, inherits parent clip/z context, and must not emit draw commands or pointer intent surfaces.
- `Stack`, `Row`, `Column`, and `Grid` are command-free structural layout group nodes emitted after QUI/QSS layout resolution. They expand children in place and must not parse QSS, own layout state, draw, or emit pointer intent surfaces.
- `Divider` projects a visual separator only. It must not emit pointer intent surfaces and should be used by composites instead of ad hoc line primitives.
- `Layer` is a command-free structural z-group. It shifts child draw-command z indexes using the resolved node `z_index`, but must not draw, own state, or emit pointer intent surfaces.
- `SafeArea` is a command-free structural clip container. It constrains child draw commands and hit testing to already-resolved logical safe-area bounds without owning state.
- `Spacer` is a command-free layout spacing node emitted after QUI layout resolution. It must not draw, own state, emit pointer intent surfaces, or affect authoritative game state.
- `Backdrop` projects a semantic overlay panel. It is visual-only unless it carries an explicit intent, in which case pointer input may resolve that intent through `@quajs/pipeline`.
- `Panel` projects a semantic container panel. It is visual-only unless it carries an explicit intent, in which case pointer input may resolve that intent through `@quajs/pipeline`.
- `Scroll` currently projects a scroll panel plus clip-start/clip-end commands, per-command clip bounds for hit testing, and already-resolved `scrollOffsetX` / `scrollOffsetY` child projection offsets. Rust may apply those offsets to draw and hit-test bounds, but it must not own persisted scroll position or authoritative UI state.
- Rust `NativeRenderer::pointer_event_and_emit_intent` may emit a resolved pointer intent through a caller-provided `NativeHostApi` as a `NativeRendererIntent` (`type` plus optional `payloadJson`). UI intent metadata from resolved QUI action descriptors must be preserved into that payload; canonical `action`, `choiceId`, and `elementId` fields from renderer intent resolution override same-named metadata so dynamic content cannot forge core dispatch identity. This is only a dispatch helper over the existing native host bridge; it must not own input authority or introduce a second event bus.
- `@quajs/engine-native` must translate Rust-emitted `NativeRendererIntent` values into `@quajs/pipeline` render-to-logic events. `choice/select` requires a string `choiceId`; `ui/intent` preserves generic `{ action, elementId, ...metadata }` payloads and only maps conventional `open` / `close` / `update` actions to overlay request shortcuts.
- Native QUI nodes may carry `UiSurfaceResolvedStyle`, representing already-resolved QSS declarations from compiler/runtime tooling.
- `@quajs/native-ui-compiler` owns QSS declaration normalization through `resolveNativeQssDeclarations` and related resolved-style types. It should emit `NativeQssResolvedStyle` plus node-level `zIndex` metadata from already parsed declarations; Rust/wgpu must consume this resolved shape instead of parsing QSS declarations.
- `@quajs/native-ui-compiler` owns `compileNativeUiSurfaceProjection`, which lowers analyzed `NativeQuiDocument.tree` plus analyzed QSS rules into camelCase `NativeUiSurfaceProjection` / `NativeUiSurfaceNodeProjection` JSON compatible with Rust `UiSurfaceNodeProjection`. When compiling dynamic package surfaces, pass explicit `contentPackageId` / `requiredRuntimePackages` so the emitted node-level `provenance` reaches Rust draw commands, resource requests, memory metrics, and unload blockers. This is a tooling/compiler boundary only; Rust renderers must continue to reject malformed projection JSON rather than loading QUI/QSS source text.
- Native QSS property value completions and hover metadata must come from the shared `@quajs/native-ui-compiler` registry so the compiler, language server, VSCode extension, and benchmark paths do not duplicate supported value lists.
- Native QSS diagnostics for native-wgpu supported properties must reuse the same parser semantics as resolved style generation and reject invalid values before projection with `QSS_INVALID_VALUE`; do not let Rust infer fallback meaning for malformed QSS values. `background-color`, `border-color`, and `color` accept only safe native color literals: hex, comma-form `rgb(...)` / `rgba(...)`, `transparent`, `currentColor`, or basic named colors. Browser `url(...)`, path-like strings, traversal markers, arbitrary CSS color functions, percentages, and malformed numeric channels must be diagnostics before projection.
- Native QUI `src` / `image` resource props must be package-relative string literals, and `asset-type` must be a safe native asset kind. `@quajs/native-ui-compiler` should emit `QUI_INVALID_ASSET_REFERENCE` for URLs, absolute paths, traversal, non-literal asset expressions, or invalid asset kinds, and projection must not pass unsafe image resources to Rust.
- Current native resolved QSS projection fields are `background-color`, `background-image`, `background-position`, `background-size`, `border-color`, `border-radius`, `border-style`, `border-width`, `bottom`, `color`, `display`, `font-family`, `font-size`, `font-style`, `font-weight`, `inset`, `left`, `right`, `top`, `width`, `height`, `min-width`, `max-width`, `min-height`, `max-height`, `letter-spacing`, `line-height`, `text-align`, `text-decoration`, `text-overflow`, `text-transform`, `white-space`, `object-fit`, `opacity`, `overflow`, `padding`, `padding-top`, `padding-right`, `padding-bottom`, `padding-left`, `visibility`, and `z-index`; `background-image` is emitted as structured package-relative `asset(...)` metadata in `UiSurfaceResolvedStyle.backgroundImage`, never as browser `url(...)`, `background-size` is a fit subset, `background-position` is an origin subset, `border-style` supports `solid` / `none` only and `none` suppresses border draw params, `font-style` - Rust background media origin consumption supports resolved keyword origins plus `0%..100%` one-axis or two-axis percentage origins from native UI/QSS tooling, such as `25%`, `25% 75%`, `top 25%`, and `right 75%`. This is projection consumption only; selector parsing, cascade, invalid value diagnostics, and QSS fallback semantics stay in `@quajs/native-ui-compiler` / LSP.
- Do not add QSS selector parsing or CSS cascade logic to `quajs_wgpu_renderer`; add those to the dedicated QSS compiler/language-server/tooling layer and emit resolved projection fields for native rendering.
- Native capability manifests must declare any consumed QSS features and QUI components so runtime packages can check compatibility before activation.
- The `native-wgpu.ui.surface@1` capability must declare the declarative asset kinds it can consume, including `qui`, `qss`, and `tokens`, so dynamic QPK compatibility metadata matches the renderer resource ledger for `UiAst`, `QssStyle`, and `TokenTable`.

- Does native host API avoid arbitrary filesystem, shell, network, dynamic library loading, and Rust callbacks?
