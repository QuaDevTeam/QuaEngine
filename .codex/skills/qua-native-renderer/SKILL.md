# Qua Native Renderer

Use this skill for `packages/native/*`, Rust native runtime/renderer crates, native host contracts, native asset/store adapters, QUI/QSS native authoring, and native packaging.

## Boundaries

- Native renderer is a projection layer only.
- Engine/store remain authoritative for game state, save/load, settings, audio intent, UI overlays, runtime packages, and plugin state.
- Communication uses `@quajs/pipeline` and render-core/plugin projections; do not add a second event bus.
- Runtime content remains Quack-built QPK packages. Dynamic QPKs may contain QS/JS modules and resources only, never native code.
- Native runtime package guards must scan script/plugin/scene/migration asset references, their runtime module variants, emitted bundle asset names, paths, relative paths, variant names/paths, and declared UI/media/resource metadata references for empty or suffix-only names, absolute/remote/traversal references, and forbidden native payload extensions before QuickJS evaluation. Resource metadata scanning is intentionally scoped to resource-like fields such as `assets`, `resources`, `surface`, `style`, `tokens`, `qui`, `qss`, `audio`, `video`, `image`, `poster`, `fallbackImage`, `assetName`, `module`, `path`, `relativePath`, `src`, `name`, `url`, `uri`, and `href`; ordinary compatibility strings such as package names, version ranges, capability ids, QSS feature names, and QUI component names must not be treated as package asset references. Guards must also reject package-level and plugin-level native-code declarations such as `nativeBinaries`, `nativePayloads`, `nativeEntry`, or truthy `nativeCode`, not only compatibility metadata. Package-level and plugin-level native renderer compatibility blocks (`metadata.nativeRenderer` and `metadata.renderers.native`) must explicitly declare `nativeCode: false`; missing or truthy values are blockers before signature verification.
- Native version/capability data comes from the signed native app/Rust build and is exposed through `QuaNativeHostInfo`; QPK content cannot override it.
- Rust native startup must fill `QuaNativeHostInfo.runtime.quickjsVersion` from `quickjs_runtime_version()`. Builds without an installed QuickJS evaluator report `unsupported`; do not leave the startup host info at `pending` or claim a real QuickJS engine version before a backend exists.
- Native `target-bundle-manifest.json` files must record `nativeRuntime.quickjsVersion`, `nativeRuntime.nativeRuntimeVersion`, `nativeRuntime.assetAdapterVersion`, and `nativeRuntime.storeAdapterVersion` from the packaged native host/adapters. `@quajs/engine-native` must compare all four fields against `QuaNativeHostInfo.runtime` before exposing the native host plugin as initialized, so a stale manifest cannot start QuickJS or renderer work against a different signed native runtime.
- Native runtime package compatibility may be declared as `metadata.nativeRenderer` or target-scoped `metadata.renderers.native`; checks normalize `renderer`/`rendererPackage` to `packageName`, `version`/`rendererVersion` to `versionRange`, and `capabilityIds`/`optionalCapabilityIds` to capability requirement lists before activation. Required `assetKinds`, `intentEvents`, `qssFeatures`, and `quiComponents` must be checked against host renderer capabilities before activation; optional asset kinds, optional intent events, optional QSS features, and optional QUI components may warn and fall back without blocking activation. Native compatibility blocks must explicitly declare `nativeCode: false`; missing or truthy values are rejected before signature verification or script evaluation. Dynamic UI package builders and third-party native renderer entries should use `createNativeUiSurfaceCompatibility` or `@quajs/native-ui-compiler`'s `createNativeUiSurfaceCompatibilityFromDocuments` so `native-wgpu.ui.surface@1`, `qui` / `qss` / `tokens`, renderer package metadata, document-derived intent events / QSS features / QUI components / asset kinds, and `nativeCode: false` stay consistent with the actual renderer capability manifest without inventing undeclared audio/video capabilities.
- Native dynamic module loading must use `createNativeRuntimeModuleLoader` or an equivalent restricted loader. It may load only runtime-package-declared, package-relative JavaScript module-like `assetName` script assets (`.js`, `.mjs`, or `.cjs`) through QuaAssets/native host bytes, then pass code to a trusted Rust/QuickJS evaluator. The loader itself must reject empty or suffix-only names, backslash paths, absolute paths, URLs/URI schemes, traversal, unsafe runtime module variant asset/module references, and native payload-looking extensions before asset lookup as defense in depth, even though trust policy guards run before activation. Do not load runtime modules from filesystem paths, URLs, Node resolution, Web `Blob`, or dynamic `import()`.
- Rust `quajs_native_runtime` QuickJS request validation must mirror the restricted TS loader and shared contracts helper: package-relative asset names only, JavaScript module-like extensions only (`.js`, `.mjs`, `.cjs`) after stripping inert `?query` / `#hash` suffixes, explicit native-payload rejection after stripping the same suffixes, module bytes and UTF-8 code bytes capped by `maxModuleBytes`, and no filesystem/URL/native payload escape hatches before evaluator dispatch.
- `@quajs/native-contracts` owns `validateNativeQuickJsEvaluationRequest` / `assertNativeQuickJsEvaluationRequest` for the shared QuickJS wire boundary. `@quajs/engine-native` must call this assertion immediately before `host.evaluateQuickJsModule`, so manually constructed evaluation requests are blocked before reaching Rust even when they bypass the higher-level runtime module loader.
- When using the native host QuickJS bridge, `moduleNamespaceId` is only an opaque Rust/QuickJS namespace handle. `@quajs/engine-native` must use an explicit namespace resolver before returning a real engine module namespace object; do not fake module exports from the id string.
- Native host QuickJS cleanup APIs (`releaseQuickJsModuleNamespace`, `releaseQuickJsPackageNamespaces`, `getQuickJsNamespaceSummary`, and `getQuickJsPackageNamespaceSummary`) are resource-ledger APIs only. Real hosts must use a persistent `QuickJsModuleNamespaceRegistry` across evaluation/release calls, not a per-request temporary registry, so runtime package unload can release package-owned namespace handles and check memory summaries. QuickJS namespace summaries must expose `moduleBytes`, `codeBytes`, and `totalBytes` so dynamic-package unload checks, dashboards, and benchmarks can compare total retained JS memory without recomputing it differently at each caller.
- `@quajs/engine-native` must release package-owned QuickJS namespaces from the late renderer-facing runtime-package unload event (`LogicToRenderEvents.RUNTIME_PACKAGE_UNLOAD`), after runtime engine plugins have been unloaded. It should call `releaseQuickJsPackageNamespaces(packageId)` when the host supports it, so successful QuickJS namespace handles do not outlive their owning Runtime QPK without being released before plugin teardown. Cleanup failures must be recorded and reported as recoverable `render/error` events with phase `quickjs-cleanup`; they must not block or rethrow from the runtime-package unload pipeline.
- Rust `quajs_wgpu_renderer` consumes resolved QUI/QSS projection data only. QSS parsing, selector matching, cascade, inheritance, and language-server diagnostics belong in TS/compiler/tooling packages, not in the renderer.
- Rust `quajs_wgpu_renderer` projection DTOs serialize/deserialize the native bridge JSON boundary with camelCase fields. Native UI surface node `kind` values must stay aligned with QUI registry component names such as `Box`, `Text`, and `Button`; the JSON facade must reject missing or null resolved surface node `kind` fields instead of silently defaulting to `Box`. Do not add Rust-side parsing of QUI/QSS authoring syntax to make up for malformed projection JSON.
- Rust `quajs_wgpu_renderer` JSON facade must require resolved native UI surface nodes to explicitly provide `visible` before serde defaults can apply. `@quajs/native-ui-compiler` must emit `UiSurfaceNodeProjection.visible` for every projected node, using `true` when no QUI `show`, QSS `display: none`, or QSS `visibility: hidden` rule overrides it. Direct Rust DTO builders may still default node visibility for internal tests, but native app / QuickJS bridge JSON must not silently turn malformed resolved QUI/QSS projection nodes into visible UI.
- Rust `quajs_wgpu_renderer` exposes `NativeRendererJsonFrameInput` and JSON facade methods for native app / QuickJS bridge ingestion of already-resolved layout, container, and view projection data. These helpers may deserialize camelCase bridge JSON and call existing frame preparation/rendering paths, but they must not parse QUI/QSS authoring syntax or become renderer-owned game state.
- Rust `quajs_wgpu_renderer` JSON facade must require the top-level resolved `view` projection to be explicitly present before serde defaults apply. The native app / QuickJS bridge must not accept `{}` or layout-only JSON as an empty valid frame, because that can hide a missing engine projection and incorrectly advance renderer state.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe native bridge stage inputs before frame preparation. Validate `NativeRendererJsonFrameInput.layout` and `.container` fields for finite positive dimensions, finite positive bounded aspect ratios, non-inverted aspect intervals, finite positive bounded `devicePixelRatio`, and finite non-negative bounded safe-area insets. The lower-level stage layout resolver may normalize internal caller values, but the JSON bridge must fail malformed app / QuickJS input instead of silently falling back.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe package asset references before frame preparation, backend submission, or audio planning. Validate known projection `assetName` fields and declarative UI surface `key` fields for empty or suffix-only names, URLs/URI schemes, absolute paths, backslash paths, traversal, and native payload-looking extensions after stripping `?query` / `#hash` suffixes. Validate known projection `assetType` fields as safe native asset-kind identifiers so resolved JSON cannot inject paths, URL schemes, or empty resource namespaces into renderer resource IDs. Validate resolved dialogue/UI `fontFamily` names because they become `fonts:*` resource ids; they may contain normal font-name spaces but must not be empty, URL/scheme-like, path-like, traversal-like, query/hash-suffixed, namespace-separated with `:`, control-character-bearing, or native payload-looking. Validate resolved dialogue/UI color fields (`RichTextStyle.color`, `UiSurfaceResolvedStyle.backgroundColor`, `borderColor`, and `color`) as safe native color literals only: hex, `rgb(...)`, `rgba(...)`, `transparent`, `currentColor`, or basic named colors. Rust should defensively reject malformed resolved JSON, but it must not parse QSS or infer fallback meaning for invalid color syntax.
- Rust `quajs_wgpu_renderer` JSON facade must require resolved image resource projections to explicitly provide `assetType` before serde defaults can apply. This includes `DialogueAvatarProjection.avatar.assetType`, `UiSurfaceNodeProjection.image.assetType`, and `UiSurfaceResolvedStyle.backgroundImage.assetType` in native app / QuickJS bridge JSON. Direct Rust DTO builders may still default image asset type for internal tests, but bridge JSON must not silently turn malformed resolved UI/dialogue resources into `images:*` resource ids.
- Rust `quajs_wgpu_renderer` JSON facade must also reject unsafe package provenance ids before frame preparation, because `contentPackageId` and `requiredRuntimePackages` flow into draw commands, resource ownership, memory metrics, and package unload blockers. Validate known projection provenance fields for empty/whitespace ids, URL/URI schemes, absolute/path-like ids, traversal markers, query/hash suffixes, control characters, and non-identifier characters; Rust should reject malformed resolved JSON rather than letting unsafe package ids pollute renderer ledgers.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe non-UI projection identity fields before frame preparation. Validate background layer `id`, character `id`, choice `id`, and audio track `id` with the same safe native identifier rules used for UI dispatch identifiers, and require each of those ids to be unique within its owning frame scope. These ids become draw command ids, renderer intents, resource ids, audio backend track ids, or memory/resource ledger identities.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved UI dispatch identifiers before frame preparation. Validate overlay `elementId`, overlay `overlayStack`, scene shell `overlay.overlayStack`, UI scene `id`, UI surface node `id`, intent `action`, canonical `choiceId`, and UI intent metadata keys for empty values, surrounding whitespace, control characters, dangerous URL/native/shell/FFI-like URI schemes, query/hash suffixes, absolute/path-like values, traversal markers, native payload-looking suffixes, and unsafe characters. Overlay `elementId` values must be unique within a frame's UI overlay list, UI scene `id` values must be unique within a frame's UI scene list, and UI surface node `id` values must be unique within each resolved surface tree, because these fields become draw command ids, hit-test element ids, scene/surface identities, overlay grouping/sort keys, or renderer intent dispatch payloads. Malformed resolved JSON must fail before command graph construction.
- Rust `quajs_wgpu_renderer` JSON facade must require resolved UI intents to explicitly provide `event` before serde defaults can apply. Direct Rust DTO builders may still default `UiIntentProjection.event` for internal tests, but native app / QuickJS bridge JSON must not silently default a malformed intent to `ui/intent`.
- Rust `quajs_wgpu_renderer` JSON facade must cap resolved UI intent metadata before frame preparation because it is copied into native host `NativeRendererIntent.payloadJson`. Metadata keys must pass the safe dispatch identifier rules, and metadata payloads must stay within native renderer limits for entry count, total estimated bytes, string bytes, array/object fanout, and nesting depth. This is only a resolved payload guard; Rust must not parse business-specific action semantics or mutate engine state from metadata.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved UI geometry before frame preparation. Validate `UiSurfaceNodeProjection.bounds` coordinates and scroll offsets as finite logical values within native renderer limits, require every resolved native UI surface node to explicitly provide `bounds.x`, `bounds.y`, `bounds.width`, and `bounds.height` before serde defaults can apply, and validate `bounds.width` / `bounds.height` as finite, non-negative logical dimensions within native renderer limits. This is a resolved-projection guard only; it must not add Rust-side QUI/QSS layout parsing or renderer-owned layout state.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved UI style numbers before frame preparation. Validate node `opacity`, style `opacity`, `backgroundPosition`, `borderRadius`, `borderWidth`, `fontSize`, `letterSpacing`, `lineHeight`, and `padding` as finite values inside the native renderer limits, with opacity/background positions normalized to `0..=1` and logical style values non-negative. Rust must reject malformed resolved JSON rather than silently clamping or reinterpreting QSS semantics.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved UI text payloads before frame preparation. Validate `UiSurfaceNodeProjection.text` for native renderer text payload limits and unsupported control characters before it enters button/text draw params or future glyph layout. This is a resolved bridge guard only; QUI content-model validation, localization policy, text interpolation, and rich text authoring semantics remain in TS compiler/tooling.
- Rust `quajs_wgpu_renderer` JSON facade must require resolved dialogue projections to explicitly provide `visible` and `mode` before serde defaults can apply. Direct Rust DTO builders may still default `DialogueProjection.visible` and `.mode` for internal tests, but native app / QuickJS bridge JSON must not silently default an omitted dialogue visibility or mode because that can hide a missing engine/compiler projection field and change hidden-vs-visible or narration-vs-say rendering semantics.
- Rust `quajs_wgpu_renderer` JSON facade must require resolved choice projections to explicitly provide `view.choices.visible`, `view.choices.choices`, and each choice `enabled` field before serde defaults can apply. Direct Rust DTO builders may still default choices to visible/enabled for internal tests, but native app / QuickJS bridge JSON must not silently turn omitted choice visibility or enabled state into visible, clickable UI.
- Rust `quajs_wgpu_renderer` JSON facade must require resolved character projections to explicitly provide each character `visible` field before serde defaults can apply. Direct Rust DTO builders may still default character visibility for internal tests, but native app / QuickJS bridge JSON must not silently turn omitted character visibility into visible sprites.
- Rust `quajs_wgpu_renderer` JSON facade must require resolved UI projections to explicitly provide `view.ui.visible` before serde defaults can apply. Direct Rust DTO builders may still default UI visibility for internal tests, but native app / QuickJS bridge JSON must not silently turn an omitted UI visibility field into visible overlays.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved dialogue/rich-text payloads before frame preparation. Validate plain dialogue text, speaker text, rich-text span text, and the aggregate `rich_text_to_plain_text` byte length for native renderer text payload limits and unsupported control characters before they enter `TextDrawParams` or future glyph layout. This is a resolved bridge guard only; dialogue authoring policy, localization, interpolation, and rich-text syntax semantics remain in engine/compiler/tooling.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved z-order values before frame preparation. Validate background layer `zIndex`, character `layer`, UI overlay / scene overlay `stackPriority` and `zIndex`, and UI surface node `zIndex` against native renderer limits before they enter overlay sorting, render graph z ordering, hit testing, or command generation. Internal render graph sorting should still use saturating arithmetic as defense in depth, but malformed bridge JSON must fail instead of relying on saturation.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved dialogue/rich-text numbers before frame preparation. Validate `RichTextStyle.fontSize` and `lineHeight` on speaker style, document style, and span style as finite positive logical values inside native renderer limits. These values become text draw parameters and font resource planning context, so malformed resolved projection must fail before command construction rather than falling back to default typography.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved background/video numbers and origins before frame preparation. Validate background and layer `x` / `y`, optional `width` / `height`, `scale`, `rotation`, and `opacity`, plus video projection `opacity`, as finite values inside native renderer limits; dimensions must be non-negative, scale must be greater than 0, rotation must be finite and bounded, and opacity must be normalized to `0..=1`. Validate background, layer, and video `origin` strings as resolved native origin values only: `left|center|right`, `top|center|bottom`, or `0%..100%` percentage axes in one-axis or two-axis form. URL, path, traversal, URI-scheme, empty, overlong, control-character, or out-of-range percentage origins must fail before command construction. This is a resolved projection guard for background layout, image/layer transform projection, and video poster/fallback projection only; it must not parse QSS, silently clamp malformed projection values, or declare real video decode support.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved character numbers before frame preparation. Validate character position `x` / `y`, `xPercent` / `yPercent`, optional `width` / `height`, `scale`, `rotation`, and character `opacity` as finite values inside native renderer limits; dimensions must be non-negative, scale must be greater than 0, and opacity must be normalized to `0..=1`. This is a resolved projection guard for character draw command planning only; Rust must not silently fall back from malformed character projection values that should have been rejected by tooling or engine projection.
- Rust `quajs_wgpu_renderer` JSON facade must reject unsafe resolved audio numbers before frame preparation. Validate audio track `volume` as a finite normalized `0..=1` value and audio track memory estimate fields (`bufferCpuBytes`, `streamCpuBytes`, `handleCpuBytes`) against native renderer limits before they enter backend command planning, memory metrics, or package unload blockers. This is still renderer-local projection/resource validation, not a real audio playback capability declaration.
- Rust `quajs_wgpu_renderer` JSON facade must require resolved native audio tracks to explicitly provide `assetType`, `loadMode`, and `playbackState` before serde defaults can apply. Direct Rust DTO builders may still default them for internal tests, but native app / QuickJS bridge JSON must not silently default a voice/sfx/ambient track to `bgm` resources, default an omitted load strategy to `buffered`, or default an omitted playback intent to `playing`.
- Rust `quajs_wgpu_renderer` JSON facade must reject Web/audio projection aliases in resolved native JSON before serde can ignore them. Audio tracks must use native bridge fields such as `assetName`, `playbackState`, and `looped`; `assetKey`, `state`, `loop`, and `playing` are unsupported resolved JSON fields and must fail before frame preparation instead of being silently defaulted or reinterpreted.
- Rust `quajs_native_app` may use `QUA_NATIVE_RENDERER_SMOKE_FRAME` to read an already-resolved projection JSON fixture and submit it through `NativeRendererJsonFrameInput` plus `NullNativeRenderBackend` as a debug/CI smoke check. It should emit both a human-readable summary and a machine-readable `Qua native renderer smoke json: ...` line with missing-resource, fallback, fallback-by-owner-package / fallback-by-required-package, texture upload request/sync, declarative resource, total memory, memory-by-kind, memory-by-package, declarative package memory, audio package memory, audio resource, and active audio track metrics. Texture sync smoke fields must include pending, resident, and orphaned resident texture counts from `NativeRendererFrameResult.texture_upload_sync`; these are host-facing upload readiness metrics. `quajs_native_app::texture_sync` owns the host/app bridge from pending texture requests to package-scoped `NativeHostApi::read_asset_bytes` reads and an upload sink, with a feature-gated real WGPU sink that decodes encoded image bytes through `upload_image_texture_bytes_with_metadata` and releases frame host-cleanup / orphaned resident decoded textures through the sink release hook. Package-scoped texture requests must resolve through mounted bundle candidates from owner/required package provenance; if no mounted bundle matches those package candidates, texture sync must report a missing asset and must not fall back to an unscoped host asset read. The helper `render_frame_with_host_texture_sync` must prepare the frame, release `NativeRendererFrameUpdate.host_cleanup` texture / decoded-image records before submitting the current frame, submit once, upload pending texture assets, release orphaned resident texture resources, and resubmit the same prepared frame only when uploads succeeded so backend draw resource state can see resident textures in that frame cycle; if only cleanup/release happened, the helper must refresh or preserve a post-cleanup texture sync snapshot without resubmitting. `render_json_frame_with_host_texture_sync` must parse and validate `NativeRendererJsonFrameInput` through the Rust JSON facade before calling the texture sync path, so unsafe resolved asset refs fail before host reads. The real-wgpu runtime may copy a completed offscreen frame target to an external `COPY_DST` texture through `copy_frame_to_texture`; this is only a swapchain-present handoff primitive, not a complete window/surface loop. This bridge must preserve package provenance in upload metadata, reject unsafe asset/package references before host reads, report upload/read/release failures, avoid arbitrary filesystem/URL loading, and remain separate from the default Null-backend smoke path. When `QUA_NATIVE_RENDERER_SMOKE_BUDGET` points to a JSON budget file, startup should fail if any smoke metric exceeds its configured max, including frame/backend command complexity, declarative resource counts, resource package/kind counts, fallback-by-package counts, texture upload request/sync counts, total memory, resource-kind memory, package owned/dependent memory, declarative package memory, and audio package memory; CLI smoke tests must cover both passing and failing texture sync, frame/backend/declarative scalar budgets, fallback package count, and kind/package/declarative/audio package budget maps. This hook and budget gate must not load QUI/QSS authoring files, ordinary plugins, Web/Cocos/native target core bootstrap arrays, Runtime QPK executable dependencies, or any native payloads.
- `quajs_native_app::texture_sync` owns app-level package release / renderer clear texture cleanup helpers. `release_package_resources_with_host_texture_cleanup` / `clear_renderer_with_host_texture_cleanup` and their audio-teardown variants must call the renderer release/clear API first, then route returned `NativeRendererHostCleanupRecord` entries through `sync_texture_releases_from_host_cleanup`. The sync helper may call the upload sink release hook only for `Texture` and `DecodedImage` records, must report already-missing texture handles as non-fatal missing entries, must record release failures, and must ignore declarative/non-texture records such as `UiAst`, `QssStyle`, and `TokenTable` so package release / clear cleanup cannot confuse QUI/QSS ledger resources with GPU textures. Blocked package release must leave resident texture handles untouched.
- `quajs_native_app::texture_sync` owns an app-level mounted bundle lifecycle registry for texture resources. `NativeTextureBundleMountRegistry` records the last host-observed runtime package bundle set from `NativeHostApi::list_mounted_bundles`, and `sync_mounted_texture_bundle_lifecycle_from_host` compares it with the current host set before a product frame loop or app lifecycle tick. First sync only establishes a baseline; later host unmounts call renderer package release plus host texture cleanup for removed packages. Packages blocked by active renderer unload guards remain tracked so later lifecycle syncs retry instead of silently dropping resident texture handles. `render_frame_with_host_texture_lifecycle_sync` is the product-loop convenience path: it runs resolved projection frame texture sync first, then applies mounted-bundle lifecycle cleanup so stale frame references from the previous projection do not falsely block package texture cleanup. Product loops with an active native audio backend should use the `*_and_audio_teardown` lifecycle variants so package-scoped audio teardown succeeds before package texture handles are released; audio teardown failures must preserve registry tracking, renderer resources, backend tracks, and resident texture handles for retry. This is transient app/host resource management only; it does not make Rust authoritative for runtime package state or bypass `RuntimeContentManager`.
- Rust `quajs_native_app` also has a feature-gated `native-window` smoke path. With `--features native-window` and `QUA_NATIVE_RENDERER_WINDOW_SMOKE=1`, it enables image decoding, creates a `winit` window, creates/configures a real `wgpu::Surface`, bootstraps `RealWgpuNativeRenderRuntimeTarget` through `create_real_wgpu_surface_target`, renders an already-resolved `NativeRendererJsonFrameInput` through a real `WgpuNativeRenderBackend`, syncs fixture UI texture requests through an in-memory `NativeHostApi` plus `render_json_frame_with_host_texture_lifecycle_sync`, applies frame host cleanup release, decodes/uploads those textures into the real WGPU backend, resubmits the prepared frame after successful uploads, then runs mounted-bundle lifecycle sync through the same product-loop ordering. It handles basic `winit` resize/scale-factor events by reconfiguring the surface and resizing the backend target, converts `winit` cursor/mouse input into native pointer events, cancels transient pointer presses on cursor-leave or focus-loss, records focus/keyboard/IME event counts without persisting raw typed text, emits focus/blur and default keyboard input-command intents through the in-memory `NativeHostApi`, and runs a one-shot deterministic pointer probe against the default resolved UI fixture so the Rust renderer can emit a `NativeRendererIntent` through the existing native host bridge. It recovers `Lost` / `Outdated` present acquisition by reconfiguring the current surface size and retrying redraw, and attempts to acquire/present the surface. It emits `Qua native window smoke json: ...` with adapter, surface format, present mode, `presented`, `presentStatus`, attempt count, resize count/last resize dimensions, `surfaceRecoveryCount`, texture upload counts, texture lifecycle sync/baseline/tracked/blocked/release/cleanup-error counts, pointer event/dispatch/intent/probe/cancel counts plus the last emitted intent type, focus gain/loss counts plus focus intent emit count, keyboard press/release/repeat counts plus keyboard intent emit count, IME event/preedit/commit counts plus last committed/preedit byte length, dimensions, pass/command counts, and submitted command-buffer count; texture upload error counts include host read/upload failures, orphan release failures, and frame host cleanup release failures. `presented=false` with `OccludedAfterRetry` means window/surface/offscreen rendering ran but the OS never exposed an acquirable visible swapchain texture, so do not claim swapchain presentation was verified in that environment. This smoke must not load Web/Cocos/native target core bootstrap arrays, ordinary plugins, Runtime QPK executable dependencies, filesystem/network assets, or native payloads; fixture texture bytes remain in-memory host assets only.
- Rust `quajs_wgpu_renderer` may bootstrap an externally owned real-wgpu surface into a `RealWgpuNativeRenderRuntimeTarget` through `create_real_wgpu_surface_target`, including adapter selection, device/queue creation, native surface config planning, and `surface.configure`. It may also plan and apply real-wgpu surface configuration behind the `real-wgpu` feature through `configure_wgpu_surface_for_native_renderer`, requiring swapchain textures to support `RENDER_ATTACHMENT | COPY_DST` so `copy_frame_to_texture`, `present_frame_to_surface_texture`, and `present_frame_to_surface` can hand off the offscreen frame to a swapchain texture. Real-wgpu runtime devices may resize their target from a new surface configuration through `resize_target_from_surface_config`; resize must rebuild frame uniforms and the offscreen frame target while preserving reusable GPU resources, and must clear cached pipelines/bind groups when the surface color format changes. The native app now has a feature-gated one-shot window smoke with basic resize reconfiguration, `Lost` / `Outdated` present recovery, and pointer intent dispatch through `NativeHostApi`, plus app-level mounted bundle lifecycle cleanup helpers for texture resources; product window ownership, continuous frame scheduling, full device/surface lifecycle recovery, and product input/focus/IME integration remain separate work.

## Package Responsibilities

- `@quajs/native-contracts`: serializable native host, renderer capability, compatibility, QUI/QSS, and target bootstrap contracts. Packagers should use `createTargetCoreSelection` to derive the active Web/Cocos/native resolver identity, core family, and selected adapters from one target value; native packagers should use `createNativeCapabilityManifestPayload` / `createNativeCapabilityManifestHash` with an injected SHA-256 implementation when emitting `nativeRenderer.capabilityManifestHash`; use `createTargetBundleNativeRendererInfo` to derive native target-bundle renderer metadata from the actual renderer capabilities. Keep `@quajs/native-contracts` platform-neutral and covered by source-level import isolation tests so shared validation code does not import Web, Cocos, or native runtime adapter packages.
- `@quajs/engine-native`: engine plugin/adapter that reads native host info, registers renderer capabilities, supplies runtime package compatibility guards, and exposes the restricted native `RuntimeModuleLoader` over package asset bytes plus a Rust/QuickJS evaluator.
- `@quajs/engine-native` also owns the native renderer intent bridge. It installs a host-side `emitRendererIntent` callback during plugin initialization, parses Rust `NativeRendererIntent` payloads, emits `choice/select` as `RenderToLogicEvents.USER_CHOICE_SELECT`, emits `ui/intent` as a generic render-to-logic UI intent, forwards `open` / `close` / `update` actions to the existing UI overlay request events, and maps native `user/input_command`, `window/focus`, and `window/blur` intents to the existing render-core render-to-logic events without creating a second event bus.
- `@quajs/assets-native`: QuaAssets adapter over native host byte/storage/crypto APIs.
- Native asset hosts should provide `listStorageKeys` when cache roots need full cleanup; `@quajs/assets-native` may fall back to index-known asset deletion when key listing is unavailable, but full orphan cleanup requires host prefix listing. Native asset cache roots are host storage prefixes and must be safe package-relative namespace paths; leading/trailing `/` may be normalized away, but empty segments, `.`, `..`, backslashes, URLs, and URI schemes are invalid.
- `@quajs/store-native`: QuaStore persistence adapter over native host storage APIs.

## Target Isolation

Web, Cocos, and native target core adapters must not be mixed:

- Web uses Web assets/renderer/framework adapters only.
- Cocos uses Cocos host/renderer only.
- Native uses `@quajs/engine-native`, `@quajs/assets-native`, `@quajs/store-native`, and Rust native runtime/renderer metadata only.
- Web, Cocos, and native core bootstrap plugins are target roots, not ordinary game plugins. They must not be placed in one shared plugin array, umbrella preset, Runtime QPK executable dependency list, or runtime resolver path that imports every target and chooses one later.
- Web, Cocos, and native packaging must use separate target-core resolver contexts. Shared validation schemas are fine, but a shared all-target core plugin list is invalid even if later filtering appears to remove inactive entries.
- Packaging to Web, Cocos, or native must begin from the active target resolver. Do not build `[webCore, cocosCore, nativeCore]` or any shared all-target bootstrap preset and filter afterward; inactive target core plugins must not be imported, registered, bundled, or kept as executable QPK dependencies.
- `@quajs/native-contracts` may be used by Web/Cocos build tooling for target validation, but it must not remain in Web/Cocos runtime bundles after tree-shaking.
- Target selection must happen before bootstrap/plugin resolution. Do not build an umbrella app that imports Web, Cocos, and native core plugins and chooses one at runtime.
- Core target plugins are reserved bootstrap infrastructure, not normal game plugins. Do not put Web/Cocos/native bootstrap adapters in ordinary plugin arrays, shared presets, Runtime QPK executable dependencies, or generated plugin resolver paths.
- Quack/native packaging should materialize one read-only `TargetCoreSelection` for `web`, `cocos`, or `native` before resolving normal engine/game plugins. Shared plugin resolution may consume that selection but must not add another target core family. The emitted `target-bundle-manifest.json` must record the matching resolver identity as `targetCoreResolver`: `web-core-resolver`, `cocos-core-resolver`, or `native-core-resolver`.
- Packaging a Web, Cocos, or native project must select exactly one target bootstrap. Target-specific renderer plugin entries and core adapters are not interchangeable between targets.
- Web, Cocos, and native project templates/starters are target-specific shells. Web starters may consume only the Web target-core resolver, Cocos starters only the Cocos target-core resolver, and native starters only the native target-core resolver; debug shells, smoke runners, installers, and updaters must consume the emitted active-target `target-bundle-manifest.json` rather than importing or re-declaring any target core adapter.
- When generating Cocos, Web, or native projects, target core plugin wiring must happen only in that target's packager resolver. Project templates, generated startup code, debug/release shells, installers, updaters, and smoke runners must never carry another target's core plugin and filter it later.
- Packaging to Cocos, Web, and native projects must keep target core plugins out of ordinary project templates entirely. A template, starter, debug shell, installer, updater, smoke runner, or runtime package that imports multiple core families and then filters by target is a release-blocking target-core leak even when the final emitted manifest appears single-target.
- Treat the three target bootstrap plugin families as disjoint: `web-core`, `cocos-core`, and `native-core`. Every packaged artifact must record exactly one selected family, and `target`, selected core adapters, renderer entries, and Runtime QPK executable dependencies must all agree with that family.
- Treat target core plugins as release-blocking isolation boundaries. Web artifacts must exclude Cocos/native core adapters, Cocos artifacts must exclude Web/native core adapters, and native artifacts must exclude Web/Cocos core adapters after bundling/tree-shaking, not just in source metadata.
- Shared engine/game/plugin code may be reused across targets only through platform-neutral entries. Shared entries must not eagerly import `@quajs/renderer-web`, `@quajs/renderer-cocos`, `@quajs/engine-native`, `@quajs/assets-native`, `@quajs/store-native`, Cocos host adapters, or native runtime adapters.
- Validate target isolation at three layers: application bootstrap core adapters, target-specific renderer/plugin entries, and Runtime QPK renderer compatibility metadata. Do not let a pass in one layer imply the others are safe.
- Use `validateExclusiveTargetBootstrap` from `@quajs/native-contracts` to assert a packaged app/startup dependency set registers exactly one Web, Cocos, or native bootstrap. Then use `validateTargetBootstrap` for the active target and treat both `missing` required target adapters and `forbidden` cross-target adapters as blockers.
- Use `validateOrdinaryPluginListTargetIsolation` from `@quajs/native-contracts` before ordinary game/plugin resolution. Quack packagers should call `assertQuackPluginReferencesTargetIsolation` / `assertLoadedQuackPluginTargetIsolation` at CLI, config, generated resolver, and loaded-plugin boundaries. Any Web, Cocos, or native target core root or subentry in `plugins`, shared presets, or generated plugin resolver paths is a blocker; target bootstrap must come only from the active target-core resolver. When ordinary plugin references include both `specifier` and `packageName`, both fields must be normalized and checked so a safe-looking package name cannot hide a target core subentry in the specifier, or vice versa.
- Use `validateTargetPluginManifest` from `@quajs/native-contracts` for third-party and official plugin source metadata before bundle entry selection. Plugin entry `target` metadata must be one of `shared`, `web`, `cocos`, or `native`; shared plugin entries must import no target core adapters, selected entries must match the active target, inactive target entries must not be eager, and target entries may import only their own target adapters plus shared logic.
- Inactive eager plugin entries must also report any Web/Cocos/native core adapter imports they would pull into the active artifact, so packagers can reject and locate target-core leakage before bundling.
- Use `validateTargetBundleManifest` from `@quajs/native-contracts` for emitted `target-bundle-manifest.json` files. Pass `expectedTarget` from the packaging/runtime context so a manifest declared for Web, Cocos, or native cannot be silently reused by another target. When `expectedTarget` is present, resolver, selected core plugin family, selected core adapters, renderer entry targets, runtime package target-core guards, artifact metadata, and native renderer metadata must all be checked against that packaging/runtime context target rather than trusting the manifest's self-declared target. It validates `targetCoreResolver`, the explicit selected core adapter set, normalized runtime dependencies, selected renderer entry targets, Runtime QPK renderer entry targets, Runtime QPK executable dependencies, `projectGraphs`, and target-scoped native renderer metadata together after bundling/tree-shaking.
- Emitted target bundle manifests may use `projectGraphs` to record project-template, startup-shell, debug-shell, release-shell, smoke-runner, installer, updater, dev-server, post-bundle, or custom dependency graphs. Non-`post-bundle` graphs must remain platform-neutral and must not declare any Web/Cocos/native target core adapter, including the active target family; `post-bundle` graphs may contain the active core family but must still reject inactive target core roots or subentries, including residual adapters from a Web/Cocos/native all-target union that was filtered too late. This lets templates and shells prove they consume the active target manifest instead of re-declaring bootstrap plugins.
- Native target bundle validation must reject missing, empty, or invalid artifact metadata required by packaging and startup, including `profile` (`debug`/`release`) and native `platform` (`macos`/`windows`/`linux`).
- Native target bundle validation must reject missing or empty release app metadata required by packaging and startup, including `app.bundleId`, `app.version`, `app.buildNumber`, and `app.icon`.
- Native target bundle validation must reject missing, non-string, or whitespace-only native renderer identity/capability metadata. `nativeRenderer.version`, `nativeRenderer.capabilityManifestHash`, and every `nativeRenderer.capabilityIds[]` value must be real non-empty strings so release artifacts cannot pass startup gates with placeholder renderer metadata.
- Native project packaging metadata should come from the unified Qua project manifest `targets.native`, including `platforms`, `profiles`, `outputDir`, `app.bundleId`, `app.version`, `app.buildNumber`, `app.icon`, native asset target, and build options.
- Quack native packaging should consume `createQuaProjectNativeArtifactPlans` so debug/release outputs are isolated by `outputDir/profile/version-buildNumber/platform` before target-bundle manifests, signing, or distribution artifacts are written.
- Quack packagers should use `emitQuaTargetBundleManifest` to validate and write Web, Cocos, and native `target-bundle-manifest.json` files with the active `expectedTarget`. Native packaging should use `emitQuaProjectNativeTargetBundleManifest` as the native artifact-plan wrapper around the shared emitter.
- Native release target-bundle manifests are immutable within a `versionSegment` + platform artifact directory. `emitQuaProjectNativeTargetBundleManifest` must reject overwriting an existing release `target-bundle-manifest.json` when the new manifest differs; debug manifests may be regenerated in place for local iteration.
- Quack/native packaging must emit a post-bundle `target-bundle-manifest.json` for every Web, Cocos, and native debug/release artifact. Native target manifests created by `createQuaProjectNativeTargetBundleManifest` automatically append a `native.<profile>.<platform>.post-bundle` `projectGraphs` record from dependencies, renderer entries, and Runtime QPK executable/renderer references; callers may pass additional template/startup/installer/updater/smoke graphs, which must stay platform-neutral. Validate the emitted manifest after tree-shaking, not just the source dependency set.
- Runtime startup must repeat the exclusive-target assertion before engine initialization so hand-built shells cannot register zero or multiple target core adapter sets. Native startup should use `createNativeEngineBootstrap` and pass the emitted `target-bundle-manifest.json` into its `targetBundleManifest` option when available, falling back to `targetBootstrapPackages` only for lightweight tests or hand-built debug shells. After reading host info, `@quajs/engine-native` must verify emitted app identity/profile/platform metadata plus native renderer package/version/backend/declared backendVersion/capability ids and capability manifest hash against the actual Rust host info before exposing the plugin as initialized.
- Rust `quajs_native_app` startup must validate native `target-bundle-manifest.json` data before building `NativeHostInfo` or starting QuickJS/engine. It can load the emitted manifest from `QUA_NATIVE_TARGET_BUNDLE_MANIFEST` and should reject unreadable/invalid manifest files, invalid artifact `profile`/`platform` values, mismatched or missing `targetCoreResolver`, missing or empty app metadata (`app.bundleId`, `app.version`, `app.buildNumber`, `app.icon`), app identity/profile/platform mismatches, missing or invalid `nativeRenderer` package/version/backend/capability metadata, missing or empty `nativeRuntime.quickjsVersion` / `nativeRuntime.nativeRuntimeVersion` / `nativeRuntime.assetAdapterVersion` / `nativeRuntime.storeAdapterVersion`, foreign Web/Cocos core roots, non-native renderer entry targets, Runtime QPK target-core executable/renderer entries, and `projectGraphs` that either declare any target core outside `post-bundle` or include inactive Web/Cocos core adapters in `post-bundle` before host-info construction. Startup dependency normalization must handle bare package specifiers, `?query` / `#hash` bundler suffixes, Windows/backslash paths, `node_modules` paths, and pnpm `.pnpm` store paths before deciding whether a dependency is Web/Cocos/native core. After constructing host info, it must compare emitted renderer package/version/backend/declared backendVersion/capability ids, capability manifest hash, QuickJS version, native runtime version, asset adapter version, and store adapter version against the actual Rust host info before QuickJS or engine startup.
- Validate package subentries by normalized package root; for example `@quajs/renderer-web/plugins/audio` is still Web core, and must not appear in native/Cocos bundles.
- Validate both `specifier` and `packageName` fields on target bundle references, plugin import references, and Runtime QPK executable/renderer references. Normalize bare subentries, `npm:` specifiers, `?query` / `#hash` suffixes, Windows/backslash paths, `node_modules` paths, and pnpm `.pnpm` store paths to package roots before target-core classification. A safe-looking `packageName` must not mask a Web, Cocos, or native target-core subentry/path in `specifier`, or vice versa.
- Shared plugin entries must not import Web, Cocos, or native core adapters. Target entries may import only their own target adapters plus platform-neutral shared logic.
- Multi-target plugin packages may declare Web, Cocos, and native entries in source metadata, but packaging must include only the active target entry and reject accidental imports of inactive target entries.
- Renderer entry records in emitted target bundle manifests must explicitly declare their target. A Web/Cocos/native artifact must fail validation if an app renderer entry or Runtime QPK renderer entry omits target metadata or declares another target, even when the entry comes from a third-party plugin package rather than an official core adapter package.
- Runtime QPKs may declare compatibility with Web, Cocos, and native, but inactive target blocks are metadata only. They must not carry executable dependencies on target core adapters, install target bootstrap plugins, or activate another target bootstrap.
- Runtime package guard must reject `executableDependencies` and `rendererEntries` that normalize to any Web, Cocos, or native target core adapter root, including target subentries such as `@quajs/renderer-web/plugins/audio`, `@quajs/renderer-cocos/plugins/dialogue`, or `@quajs/engine-native/runtime`.
- Dynamic QPK activation must evaluate only the active artifact target block. A Web build ignores native/Cocos compatibility blocks, a Cocos build ignores Web/native blocks, and a native build ignores Web/Cocos blocks while still rejecting native-code payloads for native.
- Every packaged debug/release artifact should emit a target bundle manifest and run dependency graph checks so Web builds exclude Cocos/native core adapters, Cocos builds exclude Web/native core adapters, and native builds exclude Web/Cocos core adapters.
- Runtime startup should assert exactly one target adapter set registered with the engine, so hand-built bundles cannot mix Web, Cocos, and native core plugins.
- Implement target core plugin resolution in this order: normalize target, select exactly one bootstrap preset, materialize that target's adapters/renderer/host bridge, resolve shared engine/game plugins, select active third-party target entries, bundle/tree-shake, emit `target-bundle-manifest.json`, validate it, then assert it again at runtime startup.
- Implement target core plugin resolution through target-specific functions or contexts such as Web-only, Cocos-only, and native-only resolvers. Do not let debug/release/updater/installer paths bypass the same emitted manifest validation.
- Do not introduce all-target core helpers such as `resolveAllTargetCore()`, `createCorePluginsForAllTargets()`, umbrella target core presets, or barrel exports that import Web, Cocos, and native bootstrap adapters before filtering. Target-specific resolvers may share schema and metadata helpers only when those helpers do not import inactive target bootstrap entries.
- Treat target isolation CI as two mandatory layers: a contracts suite with symmetric Web/Cocos/native fixtures for bootstrap, ordinary plugin, plugin manifest, and target bundle validation; and a packager suite that proves debug, release, installer, updater, hand-built shell, and post-bundle dependency graph paths all call the same isolation helpers. Include a negative fixture where code first constructs the Web/Cocos/native core plugin union and filters afterward; it must fail even if the final manifest appears single-target.
- Contracts target-bundle isolation tests must include both non-`post-bundle` all-target core union fixtures and `post-bundle` fixtures where the active target core is present alongside inactive Web/Cocos/native core adapters; only the active family may survive in `post-bundle`.
- Run the same source selection, renderer entry, post-bundle graph, runtime startup, and Runtime QPK gates for all three targets. Native cannot be the only strict path; Web and Cocos builds must reject native core adapters with the same severity that native builds reject Web/Cocos adapters.
- Test target isolation symmetrically. Web fixtures must reject Cocos/native leakage, Cocos fixtures must reject Web/native leakage, and native fixtures must reject Web/Cocos leakage. Native-only rejection tests are not enough.
- When packaging Web, Cocos, or Native projects, treat core bootstrap plugins as mutually exclusive roots at every layer: bootstrap selection, ordinary plugin lists, shared presets, third-party target entries, renderer entries, Runtime QPK executable dependencies, post-bundle dependency graphs, emitted manifests, installer/updater artifacts, and runtime startup. A dependency hidden in either `specifier` or `packageName` is still leakage.

Shared engine/game/plugin packages may be reused only when platform-neutral.

## QUI/QSS Projection

- Inline QUI surface nodes are renderer projections, not authoritative UI state.
- Supported foundational QUI node kinds are `Fragment`, `Box`, `Stack`, `Row`, `Column`, `Grid`, `Backdrop`, `Button`, `Divider`, `Layer`, `SafeArea`, `Spacer`, `Text`, `RichText`, `Image`, `Panel`, and `Scroll`; higher-level components such as dialog, drawer, save/load panels, gallery, and settings should compose from these base nodes.
- Imported or package-local composite QUI components are authoring-time structures only. `Dialog`, `Drawer`, save/load panels, gallery, settings, and third-party composites must be expanded or flattened by TS compiler/tooling into foundational `NativeUiSurfaceNodeProjection.kind` values before Rust receives resolved JSON; do not add arbitrary composite names to Rust surface DTOs or native-wgpu capability manifests unless they become official primitive capabilities. `@quajs/native-ui-compiler` may expand project/package composites through explicit `compileNativeUiSurfaceProjection({ components })` document maps supplied by tooling or packagers; it must not load component files from disk, QPKs, URLs, or runtime host APIs by itself.
- QUI authoring supports declarative conditional and loop directives in compiler/tooling only. `else-if` / `else` branches must be adjacent to an active conditional chain, duplicate directives on one node are invalid, `for` supports `item in source` and `(item, index) in source`, and loop-rendered nodes must declare a stable `key` so native renderers never infer list identity.
- Native QUI template expressions are evaluated only by the TS compiler's restricted evaluator. The P0 subset includes `props.*`, `view.*`, `settings.*`, loop bindings, literals, object/array literals, `== != < <= > >= && || ! ??`, and ternary for conditions, loop sources, text/prop binding, composite props, and action descriptor arguments. Do not use `eval`, `Function`, QuickJS, Rust-side parsing, arbitrary calls, assignment, mutation, `new`, or `await` for QUI expression handling.
- `@quajs/native-ui-compiler` must normalize QUI `action:` values through shared action descriptors before projection. `ui.*` emits `ui/intent` with the method as `action`, `choice.select(choiceId)` emits `choice/select`, and `save.*` / `settings.*` stay declarative `ui/intent` actions with namespaced action names. Native renderer capability manifests must declare only the actual renderer event envelopes (`ui/intent` and `choice/select` for UI surfaces), not namespaced action names such as `save/select` or `settings/change`. Do not re-parse action strings in LSP, projection compiler, or Rust renderer paths.
- Native-wgpu surface intents are currently projectable only on `Button`, `Box`, `Backdrop`, and `Panel`. `@quajs/native-ui-compiler` and the native LSP must diagnose `action:` on registered foundational components that do not emit pointer intent surfaces, such as `Image`, `Text`, `RichText`, `Divider`, `Scroll`, `Spacer`, and structural groups, using `QUI_UNSUPPORTED_ACTION_TARGET`. Projection compilation and document/projection-derived compatibility metadata must omit those non-projectable intents even if callers ignore diagnostics, and the Rust JSON facade must reject malformed resolved JSON that still carries an `intent` on a non-projectable node kind instead of silently dropping it. Developers who need clickable images, text, or scroll regions should compose them inside `Button`, `Box`, `Panel`, or `Backdrop`, or use a composite that expands to those primitives.
- Native UI `choice/select` intents must carry canonical `choiceId` on the resolved intent projection, not only inside arbitrary metadata. Rust JSON facade must reject `choice/select` UI surface intents without canonical `choiceId`; native intent serialization must let canonical `choiceId`, `action`, and `elementId` overwrite same-named metadata fields so dynamic UI content cannot forge dispatch identity. Rust JSON facade must also reject unsafe or oversized UI intent metadata before that metadata can become native host `payloadJson`.
- `@quajs/native-ui-compiler` exposes `NativeQuiDocument.tree` and `parseQuiStructureTree` as the shared authoring AST for projection compiler and LSP features; Rust native renderer must not parse QUI or QSS authoring syntax.
- QUI component registry entries must declare a content model (`children`, `text`, or `none`). Compiler/LSP diagnostics should reject nested QUI components inside `Text`/`RichText`, child content inside no-content leaves such as `Image`/`Divider`/`Spacer`, orphaned named slots, unknown parent slots, and duplicate slot blocks before Rust receives a projection tree.
- Native QUI hover metadata should come from the same component registry and expose content model, slots, and style parts instead of duplicating component documentation in the VSCode extension.
- `Fragment` is a command-free structural grouping node. It expands its children in place, inherits parent clip/z context, and must not emit draw commands or pointer intent surfaces.
- `Stack`, `Row`, `Column`, and `Grid` are command-free structural layout group nodes emitted after QUI/QSS layout resolution. They expand children in place and must not parse QSS, own layout state, draw, or emit pointer intent surfaces. If their resolved projection carries `clipChildren`, Rust may add their resolved bounds to the child clip context for drawing and hit testing without turning them into painted nodes.
- `Divider` projects a visual separator only. It must not emit pointer intent surfaces and should be used by composites instead of ad hoc line primitives.
- `Layer` is a command-free structural z-group. It shifts child draw-command z indexes using the resolved node `z_index`, but must not draw, own state, or emit pointer intent surfaces. If its resolved projection carries `clipChildren`, Rust may add its resolved bounds to the child clip context for drawing and hit testing without turning it into a painted node.
- `SafeArea` is a command-free structural clip container. It constrains child draw commands and hit testing to already-resolved logical safe-area bounds without owning state.
- `Spacer` is a command-free layout spacing node emitted after QUI layout resolution. It must not draw, own state, emit pointer intent surfaces, or affect authoritative game state.
- `Box` projects a generic rectangular paint primitive. It is visual-only unless it carries an explicit intent, in which case pointer input may resolve that intent through `@quajs/pipeline`.
- `Backdrop` projects a semantic overlay panel. It is visual-only unless it carries an explicit intent, in which case pointer input may resolve that intent through `@quajs/pipeline`.
- `Panel` projects a semantic container panel. It is visual-only unless it carries an explicit intent, in which case pointer input may resolve that intent through `@quajs/pipeline`.
- `Image` projects a package-backed image leaf only when the resolved projection carries a non-empty safe asset type/name. Missing or invalid authoring `src` / `image` values should remain compiler/LSP diagnostics; Rust may skip an empty resolved image leaf instead of emitting a meaningless empty image draw command.
- `Scroll` currently projects a scroll panel plus clip-start/clip-end commands, per-command clip bounds for hit testing, and already-resolved `scrollOffsetX` / `scrollOffsetY` child projection offsets. Rust may apply those offsets to draw and hit-test bounds, but it must not own persisted scroll position or authoritative UI state.
- Rust `NativeRenderer::pointer_event_and_emit_intent` may emit a resolved pointer intent through a caller-provided `NativeHostApi` as a `NativeRendererIntent` (`type` plus optional `payloadJson`). UI intent metadata from resolved QUI action descriptors must be preserved into that payload; canonical `action`, `choiceId`, and `elementId` fields from renderer intent resolution override same-named metadata so dynamic content cannot forge core dispatch identity. This is only a dispatch helper over the existing native host bridge; it must not own input authority or introduce a second event bus.
- `@quajs/engine-native` must translate Rust-emitted `NativeRendererIntent` values into `@quajs/pipeline` render-to-logic events. `choice/select` requires a string `choiceId`; `ui/intent` preserves generic `{ action, elementId, ...metadata }` payloads and only maps conventional `open` / `close` / `update` actions to overlay request shortcuts; `user/input_command` must validate the existing render-core command/device/source/timestamp payload shape before emitting `RenderToLogicEvents.USER_INPUT_COMMAND`; `window/focus` and `window/blur` emit the existing lifecycle events with empty payloads. Malformed renderer intent payloads must be reported as renderer errors through the existing bridge rather than dispatched through a parallel native event path.
- Native QUI nodes may carry `UiSurfaceResolvedStyle`, representing already-resolved QSS declarations from compiler/runtime tooling.
- Native composite expansion is compiler-only. Imported component documents supplied to `compileNativeUiSurfaceProjection` may use `props.*` bindings plus named slot placeholders such as `slot header` / `slot body`; invocation content replaces those placeholders before projection, loop keys scope expanded child ids, and the resulting projection must contain only foundational native-wgpu node kinds.
- `@quajs/native-ui-compiler` owns QSS declaration normalization through `resolveNativeQssDeclarations` and related resolved-style types. It should emit `NativeQssResolvedStyle` plus node-level `zIndex` metadata from already parsed declarations; Rust/wgpu must consume this resolved shape instead of parsing QSS declarations.
- `@quajs/native-ui-compiler` owns `compileNativeUiSurfaceProjection`, which lowers analyzed `NativeQuiDocument.tree` plus analyzed QSS rules into camelCase `NativeUiSurfaceProjection` / `NativeUiSurfaceNodeProjection` JSON compatible with Rust `UiSurfaceNodeProjection`. When compiling dynamic package surfaces, pass explicit `contentPackageId` / `requiredRuntimePackages` so the emitted node-level `provenance` reaches Rust draw commands, resource requests, memory metrics, and unload blockers. This is a tooling/compiler boundary only; Rust renderers must continue to reject malformed projection JSON rather than loading QUI/QSS source text.
- Native QSS property value completions and hover metadata must come from the shared `@quajs/native-ui-compiler` registry so the compiler, language server, VSCode extension, and benchmark paths do not duplicate supported value lists.
- Native QSS diagnostics for native-wgpu supported properties must reuse the same parser semantics as resolved style generation and reject invalid values before projection with `QSS_INVALID_VALUE`; do not let Rust infer fallback meaning for malformed QSS values. `background-color`, `border-color`, and `color` accept only safe native color literals: hex, comma-form `rgb(...)` / `rgba(...)`, `transparent`, `currentColor`, or basic named colors. Browser `url(...)`, path-like strings, traversal markers, arbitrary CSS color functions, percentages, and malformed numeric channels must be diagnostics before projection.
- Native QUI `src` / `image` resource props must be package-relative string literals, and `asset-type` must be a safe native asset kind. `@quajs/native-ui-compiler` should emit `QUI_INVALID_ASSET_REFERENCE` for URLs, absolute paths, traversal, empty or `.` path segments, trailing slashes, backslashes, native payload-looking suffixes, non-literal asset expressions, or invalid asset kinds, and projection must not pass unsafe image resources to Rust. The compiler, QSS parser, language-server asset index, and native UI compatibility derivation must share the same package asset-name safety helper so invalid resources cannot become document links, resolved projection image refs, or runtime compatibility `assetKinds`.
- Current native resolved QSS projection fields are `align-items`, `background-color`, `background-image`, `background-position`, `background-size`, `border-color`, `border-radius`, `border-style`, `border-width`, `bottom`, `box-sizing`, `color`, `display`, `font-family`, `font-size`, `font-style`, `font-weight`, `gap`, `row-gap`, `column-gap`, `justify-content`, `margin`, `margin-top`, `margin-right`, `margin-bottom`, `margin-left`, `position`, `inset`, `left`, `right`, `top`, `width`, `height`, `min-width`, `max-width`, `min-height`, `max-height`, `letter-spacing`, `line-height`, `text-align`, `text-decoration`, `text-overflow`, `text-transform`, `white-space`, `object-fit`, `object-position`, `opacity`, `overflow`, `pointer-events`, `padding`, `padding-top`, `padding-right`, `padding-bottom`, `padding-left`, `visibility`, and `z-index`.
- Native QSS paint/text fields are resolved by `@quajs/native-ui-compiler` before Rust sees projection JSON. `background-image` is emitted as structured package-relative `asset(...)` metadata in `UiSurfaceResolvedStyle.backgroundImage`, never as browser `url(...)`; `background-size` is a fit subset; `background-position` and `object-position` are origin subsets; `object-position` maps to `ImageDrawParams.origin` for native UI `Image` leaves; `border-style` supports `solid` / `none`; `font-style`, `letter-spacing`, `text-decoration`, `text-overflow`, `text-transform`, and `white-space` map to Rust text/button draw params through resolved style JSON while full text layout, shaping, and richer casing/wrapping remain future text backend concerns.
- `box-sizing` supports `border-box` / `content-box` as compiler-only static bounds normalization. `border-box` preserves the authored QSS fallback width/height as final native surface bounds; `content-box` expands QSS fallback width/height by resolved padding and effective border width before projection. Explicit QUI `width` / `height` props remain authoritative. Rust receives only final resolved bounds and must not parse box-sizing declarations.
- `gap` / `row-gap` / `column-gap` support one or two non-negative logical px / unitless numbers as compiler-only layout metadata that `compileNativeUiSurfaceProjection` expands into Row / Column / Grid direct-child `UiSurfaceNodeProjection.bounds`; Rust receives only resolved child bounds and must not parse gap declarations.
- `justify-content` supports `flex-start` / `center` / `flex-end` / `space-between` / `space-around` / `space-evenly` as compiler-only Row / Column main-axis distribution metadata. `align-items` supports `flex-start` / `center` / `flex-end` as compiler-only Row / Column cross-axis alignment metadata. Both expand to resolved child `bounds`; Rust receives only the final bounds and must not parse alignment declarations or implement flexbox.
- `margin` / `margin-top` / `margin-right` / `margin-bottom` / `margin-left` support one to four non-negative logical px / unitless numbers as compiler-only layout metadata consumed by Row / Column / Grid direct-child projection layout. They expand into resolved child `bounds`; Rust receives only resolved child bounds and must not parse margin declarations or implement a CSS box model.
- `position` supports `relative` / `absolute` as compiler-only layout metadata. `absolute` only removes Row / Column / Grid direct children from structural layout flow and positions them from already-resolved child `bounds` relative to the structural parent; Rust receives only resolved child bounds and must not parse position declarations or implement full CSS positioning.
- `left` / `top` / `right` / `bottom` / `inset` / `width` / `height` are emitted as static `UiSurfaceNodeProjection.bounds` fallback metadata through the TS compiler only. `right` / `bottom` only derive final `x` / `y` when the parent has resolved bounds and the current node has resolved `width` / `height`; `inset` is a non-negative top/right/bottom/left shorthand; `min-width` / `max-width` / `min-height` / `max-height` only clamp those static QSS fallback bounds in the TS compiler; explicit QUI `x` / `y` / `width` / `height` props stay authoritative.
- `display` supports `none` only and is emitted as node-level `UiSurfaceNodeProjection.visible: false` fallback metadata; `overflow` supports `visible` / `hidden` only and is emitted as node-level `UiSurfaceNodeProjection.clipChildren`; `pointer-events` supports node-local `auto` / `none` only and is compiler-only intent metadata where `none` removes that node's own resolved intent without hiding it or disabling child intents; `visibility` is emitted as node-level `UiSurfaceNodeProjection.visible`; explicit QUI `show` props stay authoritative. When no rule overrides visibility, the TS compiler emits `visible: true` explicitly for every node so Rust bridge validation never relies on serde defaults. `padding` is emitted as resolved edge inset metadata in `UiSurfaceResolvedStyle.padding`, and `z-index` is emitted as `UiSurfaceNodeProjection.z_index` rather than stored in `UiSurfaceResolvedStyle`.
- Rust background and object media origin consumption supports resolved keyword origins plus `0%..100%` one-axis or two-axis percentage origins from native UI/QSS tooling, such as `25%`, `25% 75%`, `top 25%`, and `right 75%`. This is projection consumption only; selector parsing, cascade, invalid value diagnostics, and QSS fallback semantics stay in `@quajs/native-ui-compiler` / LSP.
- Do not add QSS selector parsing or CSS cascade logic to `quajs_wgpu_renderer`; add those to the dedicated QSS compiler/language-server/tooling layer and emit resolved projection fields for native rendering.
- Native capability manifests must declare any consumed QSS features and QUI components so runtime packages can check compatibility before activation.
- The `native-wgpu.ui.surface@1` capability must declare the declarative asset kinds it can consume, including `qui`, `qss`, and `tokens`, so dynamic QPK compatibility metadata matches the renderer resource ledger for `UiAst`, `QssStyle`, and `TokenTable`.
- `createNativeUiSurfaceCompatibilityFromDocuments` should derive required `quiComponents` from analyzed QUI component nodes that are registered native-wgpu components only, required `qssFeatures` from analyzed QSS declarations, and required asset kinds from QUI `src` / `image` props plus QSS `background-image: asset(...)`. Imported authoring-only composites such as `Dialog` or `Drawer` must not become required native renderer components unless explicitly passed by the caller for a real official primitive capability. `createNativeUiSurfaceCompatibilityFromProjection` should derive the same compatibility shape from already resolved `NativeUiSurfaceProjection` data without reading QUI/QSS source. Both helpers must call the platform-neutral contracts helper, preserve `nativeCode: false`, and avoid declaring audio/video capabilities unless explicitly provided by the caller.
- Native media capability ids must describe implemented projection/resource contracts precisely. Do not declare QUI media components, real video decode, or audio playback capability until the Rust projection path and backend support exist; fallback-only video/audio capabilities should use deterministic `warn-once` semantics.
- Current UI/QSS resource tracking in `quajs_wgpu_renderer` records package-aware `UiAst`, `QssStyle`, and `TokenTable` entries with deterministic labels and conservative CPU-byte estimates for memory ledger, budget, renderer resource metrics, frame resource sync summaries, package unload summaries, and host cleanup records. Asset planning, frame metrics, renderer resource metrics with package breakdowns, frame resource sync summaries, package release summaries, host cleanup records, `native.memory_ledger.summary.smoke`, `native.package_release.summary.smoke`, `native.frame_resource_replacement.summary.smoke`, and feature-gated `native.wgpu_buffer.heavy_ui_text.smoke` benchmark output identify declarative asset/resource load, release, replacement-cleanup, unload-block pressure, and heavy QUI-style text buffer geometry pressure. Memory-ledger smoke output must include resource-kind, package, declarative-package, and audio-package memory breakdowns so dynamic QUI/QSS/token package resident memory can be benchmarked separately from image/audio/media resources. These are internal resource-ledger estimates only; real host/backend-reported resource memory must be preserved when available.
- Current native text rendering includes a deterministic built-in bitmap TextAtlas fallback for supported ASCII text, common UI punctuation, and per-character solid fallback blocks for unsupported non-whitespace glyphs in normal and italic font styles, across the resolved native `text-align`, `white-space`, and `text-overflow` subsets, including `pre` / `pre-wrap` preserved whitespace, deterministic bitmap-width wrapping, `clip` / `ellipsis` overflow behavior, and `text-decoration: none`, `underline`, and `line-through`; CJK/fullwidth fallback glyphs reserve double-width bitmap cells, and wrap-enabled oversized no-space words split by shared CJK/fullwidth glyph width in both bitmap and placeholder fallback paths so Chinese/Japanese/Korean UI text does not collapse into ASCII spacing or a single clipped line while waiting for a real font backend. Italic uses bitmap shear, and the real WGPU path samples a built-in atlas texture for atlas glyphs, unsupported-glyph solid masks, and solid decoration masks. This is still not real CJK glyph rendering, font shaping, bidi, font fallback, or a font asset rasterization backend; richer typography may still require placeholder geometry or a future text backend. Missing `FontFace`, `GlyphAtlas`, `QssStyle`, and `TokenTable` resource records must remain diagnostics/ledger signals but must not block Text, RichText, UI Button bitmap text, or placeholder fallback draw commands. Texture, video, and `UiAst` surface-source resources remain draw-blocking when the submitted frame depends on them.
- Current video work in `quajs_wgpu_renderer` is poster/fallback rendering only: video background projections emit video draw commands with fallback reasons and poster image asset requests, preserve engine-projected playback policy metadata (`loop`, `muted`, `volume`, and `playbackRate`) plus resolved fit/origin styling through native video draw params, and prepared frame/backend submission metrics report fallback counts by video/pipeline/reason plus owner/required package provenance for dynamic QPK attribution. The fallback `native-wgpu.video@1` capability declares consumed QSS features such as `object-fit`, `object-position`, and `opacity` for compatibility checks, but it does not declare QUI media components or real playback semantics. Renderer metrics expose `fallbacks_by_owner_package` and `fallbacks_by_required_package`; backend submission diagnostics expose the same provenance per fallback warning. This is not real video decode support, and playback policy metadata must not be presented as actual native video playback until a decoder/backend consumes it.
- Current audio work in `quajs_wgpu_renderer` is renderer-local resource tracking and backend command planning only: projected tracks may create `AudioBuffer`, `AudioStream`, and `AudioHandle` records, audio asset request plans, cleanup records, memory summaries, unload blockers, audio-specific resource metrics, renderer-local active backend track metrics, and `LoadAsset`/`StartTrack`/`UpdateTrack`/`StopTrack`/`ReleaseHandle` plans for a future `NativeAudioBackend`. `NativeRenderer` may explicitly apply those plans to an injected backend, must send teardown `StopTrack`/`ReleaseHandle` plans before clear when that backend is active, and may send package-scoped teardown plans before releasing inactive package-owned audio resources. `NullNativeAudioBackend` may record plans for tests. This is not playback support and must not be surfaced as `native-wgpu.audio@1` before a real decoder/mixer/device backend is implemented.

- Does native host API avoid arbitrary filesystem, shell, network, dynamic library loading, and Rust callbacks?
- Does Rust `NativeHostInfo` serialize to the TS `QuaNativeHostInfo` shape, including camelCase fields and `debug`/`release` plus `macos`/`windows`/`linux` literals?
- Does the Rust native renderer capability manifest include projection keys, intent events, asset kinds, QSS features, QUI base components, and fallback policy?

- Are video/audio native capability declarations limited to currently implemented projection/resource paths, with real decoder/playback backend support guarded by later capability updates?
- Are native renderer version/capability checks performed before dynamic package JS evaluation?
- Does `@quajs/engine-native` install `createNativeRuntimeTrustPolicy` so runtime native-code payload guards run before QuickJS module loading?

- Do native QuickJS release/summary host APIs use a persistent package-aware namespace registry, and does `@quajs/engine-native` call those APIs only as cleanup/query helpers rather than treating namespace ids as module exports?
