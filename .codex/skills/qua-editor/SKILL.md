# QuaEngine Editor

Use with `quaengine-development-guardrails`; also use `qua-native-renderer` when modifying native surface hosting or product lifecycle.

Use [qua-editor-development-guardrails](../qua-editor-development-guardrails/SKILL.md)
for workbench/plugin implementation, shared atomic forms, accessibility, source
edit boundaries and UI validation. `@quajs/editor-controls` owns common DOM
controls and `--editor-*` tokens; panel CSS should only arrange them.

## Responsibility and setup

- First-party IDE source under `packages/editor/` (including core, UI, Electron, Character Editor and Novel Writer) uses MPL-2.0, not the repository's default Apache-2.0. Keep package `license` metadata and package-local `LICENSE`/`NOTICE` aligned; preserve third-party notices. Follow `packages/editor/CONTRIBUTING.md` and the licensing section of its README. Distributions must provide the corresponding covered source and tell recipients how to obtain it; upstream PRs are encouraged, not required. Commercial use and forks remain permitted. New packages need the same license files, and moving covered code does not remove MPL obligations.
- The editor is a standalone Electron product. Do not introduce devframe or a VS Code runtime dependency.
- Run `pnpm dev:editor` from the repository root. It builds workspace prerequisites before launching Electron. Open a Qua project folder such as `demo`.
- `packages/editor/core` contains portable document and preview contracts plus lifecycle coordination. `ui` contains the host-neutral workbench. `electron` contains main/preload, Node worker services, files and child processes.
- Project inspection and QuaScript diagnostics reuse `@quajs/project-inspector` and `@quajs/language-server`; CPU-intensive project work belongs in the worker, not Electron main or UI.

## Desktop window chrome

- All desktop targets use `BrowserWindow({ frame: false })` and the workbench titlebar, without a native titlebar or titlebar overlay. Keep a native draggable region and exclude every interactive control with `app-region: no-drag`.
- macOS uses custom close/minimize/fullscreen circles on the left; Windows/Linux use minimize/maximize-or-restore/close controls on the right. All hosts show an application-menu button beside the fixed `Qua / Editor` brand. It opens a native dropdown with the shared File/Edit/Terminal/View commands, including File → Production Build. Preserve the macOS global menu; other hosts hide the attached menu bar and also support Alt+M. Keep shared command definitions/accelerators, menu anchoring, keyboard dismissal and the expanded state; do not add a standalone build button or replace the workbench brand with the project name.
- The dedicated app icon is `assets/brand/quaeditor-icon.png`, composed from the reviewed mascot by `scripts/brand/editor.py`. Keep its 824 px continuous-corner squircle centered in a 1024 px transparent canvas (100 px inset); scale and clip the pencil with the artwork. Do not use circular corners or a full-canvas tile that looks oversized in the Dock. These are flattened desktop resources, not unmasked Icon Composer layers. Electron's build emits portable PNG/ICNS/ICO resources under `dist/icons`; main loads the bundled PNG for BrowserWindow and macOS Dock (including development). Regenerate with `node packages/editor/electron/scripts/build-icons.mjs` and visually compare at small sizes and beside system Dock icons. Keep artwork out of runtime source-tree paths. Future installers must bind ICNS/ICO into bundle/executable metadata; Dock replacement alone does not prove an installed Finder/Explorer icon. Brand assets retain their reserved rights. See `assets/brand/README.md` for regeneration.
- Host-owned focus/maximize/fullscreen state reaches the UI through a bounded window-state contract and native events, never a polling timer. Window actions are explicitly allowlisted behind the existing main-frame IPC check. Close must call the existing `window.close()` guard and preview/process cleanup, never `destroy()` from a renderer request.
- `node packages/editor/electron/scripts/window-smoke.mjs` verifies the current OS's frameless geometry, control order, drag exclusions, maximize/restore, minimize, fullscreen, unknown-action rejection, dirty-document close protection and settings shortcut. Screenshots go to `.codex-tmp/editor-window-smoke/`. A macOS run is not Windows or native drag/snap acceptance; run on each supported OS for those claims.

## Files and user work

- File → New Project and the empty editor create game or plugin projects through the host directory picker. Reuse `create-qua-game` templates; exclusively reserve a new child directory and never overwrite existing files/symlinks. Keep dirty-document confirmation before replacement. Plugin projects use `quajs.extension` and hide the complete preview pane/splitter; host IPC rejects game preview for them.
- Electron build runs `scripts/build-sdk.mjs` to archive built Qua packages and their required dependency closure into `dist/sdk`. IDE-created projects copy that closure to portable `vendor/quajs` archives and use npm file dependencies/overrides until the SDK is publicly published. Preserve peer version metadata in plugin publication; never add inactive target core packages or execute package lifecycle scripts when assembling SDK archives. Ship `create-qua-game/templates` and `dist/sdk` with the app.
- `runtime/ProjectRuntime` checks actual declared dependencies (including dev tools, versions and built entry/bin files), not just the existence of node_modules. On open/create and before preview, coalesce detection/installation, report bounded progress/logs, verify after installation, and retain actionable failure/cancellation with explicit retry. Install npm/pnpm dependencies with lifecycle scripts disabled; respect pnpm lockfiles/policies. Never retry a failed install in a watcher loop. Cancel owned downloads/children before replacing a project or closing the IDE. Installed dependencies refresh the shared project/plugin/language snapshot.
- `ManagedTools` checks Node/npm and the project's pnpm version, then downloads Node LTS and Rust/Cargo as needed into the IDE profile's `runtimes` directory. HTTPS official distributions must pass SHA-256 checks before execution. Keep Node extraction staged, Rust minimal, user shell profiles unchanged, and pass the resulting environment to preview/new terminals. OS SDKs/linkers remain system prerequisites with actionable errors, not silent readiness. Do not claim Windows/Linux acceptance from macOS checks.
- Validate with `scripts/project-setup-smoke.mjs` (real temporary project creation, SDK dependency install, plugin build, Web preview and individual dependency repair) and the opt-in `QUA_EDITOR_TOOLCHAIN_SMOKE=1` runtime test (actual isolated Node/Rust downloads). Run `publishing-smoke.mjs` when changing plugin recognition. These do not publish npm packages or modify global toolchains.

- Source files and existing project/QPK manifests are the authoring truth. UI selection, window layout and preview sessions are editor-local.
- Opening/switching a source tab or navigating to a source location asks panel contributions' optional `acceptsSource(project, location)` to match the existing index. `PluginPanels` reveals the matching bottom panel without stealing source focus and delivers the latest location through optional `revealSource`; undefined cancels pending navigation. Keep lazy mounts/project changes race-safe, do not reopen dismissed panels on routine refresh, and suppress this navigation during internal save-all traversal. No plugin gets an extra filesystem scan or full host bridge. Validate with `source-panels-smoke.mjs` plus animation/character smokes.
- Scope file access to the opened canonical project root, including symlink resolution. Keep document size limits and reject generated/dependency directories.
- Save with optimistic revision checking and atomic replacement; preserve external edits and keep unsaved text on conflict. Confirm discarding edits on close or document/project replacement.
- `project-service/watcher.ts` watches the enumerated project directories only; exclude dependencies, hidden/generated directories and symlink trees. Bound enumeration to 20000 source/media/other files, 1024 directories and depth 10. Share file entries and relative directories with the tree and Assets Browser; coalesce notifications, serialize refresh with file/language requests, and discard old-project events. Surface watch/scan limits and preserve a manual refresh path. This refreshes full inspector snapshots, not an incremental index.
- Clean documents may reload external edits while preserving view position. Dirty or missing documents retain their buffers. Comparing disk changes is read-only; explicit keep-local save uses the compared disk revision, never an unconditional overwrite. Reject newer disk changes and require a new comparison. Reset neither buffers nor dirty flags during index refresh. No automatic three-way merge, save-as or crash recovery is implemented yet.
- QuaScript completion, hover, definition and formatting providers reuse existing language-server/compiler helpers in the Node worker, with unsaved source and project tooling config. Use one-based editor positions and convert zero-based compiler/LSP ranges at the adapter boundary. Reject stale/cancelled provider results and ignore in-memory diff models. Keep definition navigation within the same editable project boundary. Retain `@` when replacing decorator completion text; do not offer inactive plugin snippets.
- Do not add editor-only QuaScript grammar or plugin decorators. Compiler/LSP semantics remain shared.
- `analyzeQuaScript` returns diagnostics and AST-derived `dialogueHighlights` together. Color speaker names and literal dialogue segments from these ranges, leaving narration, comments, choice text and TypeScript interpolation unchanged. Keep the same speaker label's color across documents in a workspace; speaker aliases are not automatically merged. Reset decorations and discard stale results on document/project replacement.
- Reuse a worker-owned `QuaScriptTypeScriptSession`; dispose on project/source-index invalidation. Keep the document analysis cache bounded (32 entries), keyed by path, source and tooling configuration. Reuse the compiler parse for the virtual TypeScript document instead of parsing again for colorization.
- Background project checking covers indexed `.qs` files plus the actual tsconfig program using `checkTypeScriptProject` (no emit). It checks disk content, while the current QuaScript buffer supplies live unsaved diagnostics. Yield between files, show progress, cancel superseded checks on refresh/project changes, and deduplicate disk/live results without hiding TypeScript file diagnostics. Refresh triggers a debounced check; show only a status icon at the right of the footer (checking/clean/warning/error, tooltip details, click opens Problems), with no check text or manual-check button in the panel toolbar. Live diagnostics for open TS/JS buffers replace their disk diagnostics without hiding errors in other files.
- Configured TS/JS files also receive ESLint diagnostics, using the project's installed ESLint/parser/plugins and actual ignore rules. Discover `eslint.config.*`, supported legacy `.eslintrc*` or `package.json#eslintConfig` between the file and opened root; do not accidentally enable an unrelated ancestor config. No config means no lint, not default rules. Missing dependencies, invalid/unsupported configuration and worker failures become actionable `ESLint/*` warnings while TypeScript analysis continues. Use `lintText` with the unsaved buffer and canonical file path, one-based positions, bounded diagnostics, and `fix:false`; lint must not write source or install packages.
- ESLint configuration is executable project tooling. Live lint runs in its own disposable `lint-worker`, independent of language completion and file reads, with a 30-second deadline. Background lint reuses the indexed file list in the cancellable check worker. Refresh/project replacement terminates live lint and clears executable module caches. Watch hidden `.eslintrc*`/`.eslintignore` files without expanding hidden/dependency directory scans. Validate real project rules/ignores, missing configs/dependencies, config refresh, draft replacement and simultaneous TS/ESLint diagnostics.
- QuaScript's source context menu contributes **运行到此行** only for writable QuaScript models. Capture the actual right-click target row even inside a selection; keyboard invocation uses the current cursor. Reuse the existing `seekPreview` save/analyze/start/engine-checkpoint flow for the selected Web/Native target. Capture the line before asynchronous work, coalesce duplicate seeks, and reject results after project/model/version changes. Preserve static-error/save-conflict handling and choice pauses; never introduce a direct renderer jump or a second script parser. Check actual right-click startup from stopped Web and Native previews.

## Source languages and responsive opening

- Source opening uses bounded asynchronous filesystem reads outside the project/check/language worker queues. Reuse the same canonical project-root, symlink, extension and 2 MiB validation for reads, language requests and definition navigation. Saves/file mutations remain serialized with optimistic revisions. Read results from an old project must be discarded.
- Keep project indexing/watch mutations, interactive language work and background static checking in separate workers. The checker consumes the existing project snapshot, never rescans independently; terminate superseded checks on refresh/project switch and release its worker after completion. Neither TypeScript program creation nor diagnostics may delay opening or switching source tabs.
- Assign Monaco language ids to TS/TSX/MTS/CTS, JS/JSX/MJS/CJS, Markdown, JSON/JSONC, YAML, CSS/SCSS, HTML/Vue/Svelte and TOML. Load Monaco grammars on demand; reuse its JSON tokenizer. The Vite grammar-only transform strips Monaco 0.55 grammar artifacts' side-effect imports of the complete editor feature bootstrap while retaining bound API imports. This prevents unrelated word-highlighter observers and extra chunks from loading on first TS/YAML use; recheck this boundary on Monaco upgrades. One Monaco editor still owns the tab models and undo stacks. Indentation folding is enabled.
- The interactive worker uses TypeScript language services (project tsconfig/jsconfig, imports, completion, hover, definitions, live diagnostics and formatting), VS Code JSON services and Red Hat YAML services (syntax diagnostics, local Schema completion/hover, formatting, JSON refs/YAML anchors), and VS Code Markdown services (heading/path/reference completion, heading/reference definitions, invalid-link diagnostics). Markdown/YAML/CSS/SCSS/HTML/Vue formatting uses Prettier without loading project executable plugins/configuration. Other registered grammars provide highlighting only; do not advertise full framework/TOML semantics.
- Synchronize the set of open buffers before language queries, retaining inactive unsaved drafts and dropping closed/renamed/deleted paths. Bound synchronization to 24 models/24 MiB; queries to 2 MiB each. Apply provider replacement ranges and snippet flags, settings-based indentation, one-based source coordinates, and stale model/version/path cancellation. Ignore in-memory diff models. Pass TS/JS drafts to shared QuaScript tooling as extra files as well.
- Schema loading accepts project-local files only, including relative `$schema` and YAML language-server modelines; it does not fetch remote schemas. Invalidate schema, Markdown and TS disk caches on index refresh; invalidate affected draft caches on buffer changes. Markdown workspace queries use the existing index and cap all-document reads at 256; media hover previews remain in the Assets Browser.
- `node packages/editor/electron/scripts/languages-console-smoke.mjs` exercises actual Electron reads during background checking, tab opening and syntax colors, Monaco completion/formatting, streamed JSON disclosure/paging/escaped markup/expansion retention, and a progress UI lifecycle fixture. It records local timings and screenshots in `.codex-tmp/editor-languages-console-smoke/`. Injected progress UI events are not a real Native build acceptance; parser/controller tests cover stage evidence and stale-session rejection separately.

## Workbench, search and media

- Before forwarding child-process output to plain logs, use a separate streaming `ProcessLogDecoder` for stdout and stderr. Consume complete ANSI/VT control sequences across chunk boundaries (including clear-line, colors, cursor commands and OSC hyperlinks/titles), normalize CR/CRLF to append-only lines, and preserve literal bracket text, Unicode and JSON escapes. Clean error tails through the same path. Never strip interactive PTY/xterm data. `node packages/editor/electron/scripts/console-output-smoke.mjs` exercises actual child output through Electron IPC and Debug Console, including JSON disclosure retention and clear; parser tests cover every split boundary.

- Dedicated empty surfaces use shared `emptyState` controls (workbench `workbenchEmpty`):
  a restrained icon, clear title, brief context and an available next action. Distinguish
  no project, no file, no results and waiting for preview data. Keep console placeholders
  outside the raw log node and hide them immediately on output; restore them on clear.
  Do not reintroduce repetitive single-line onboarding rows above populated content.
  Collapse empty status rows instead of leaving a blank strip. General single-line feedback
  belongs in `ContextStatus` in the bottom footer, scoped to the active sidebar,
  panel or marketplace. Preserve original live regions/actions and full hover text.
  Plugin `context.mountStatus(element)` registrations are owned by the mount epoch;
  dispose them on project replacement, load failure and unload, and reject late
  registrations. Keep field-specific validation, blocking dialogs and build logs
  in their owning surface. Global errors remain visible alongside contextual text.

- `ui/src/workspace` owns activity-bar views (Explorer/Search/Story), resizable panes and bottom Problems/Debug Console/Terminal/Assets Browser/Inspector/Performance tabs. File tree and asset lists are virtualized. Keep tree expansion, keyboard focus, file selection, pane sizes and panel choice local to the editor; never write them into engine/store.
- Explorer, asset folders and Git trees use 22px virtual rows, shared 12px depth increments, aligned chevron/file-icon columns and CSS-only ancestor guides. Git groups, folders and files use the same node columns and selection surfaces as Explorer. The redundant project-name/file-count row is removed; the tree host keeps the project name as a non-visual data attribute for lifecycle and test synchronization. Update virtual row sizing together with visual density so hit targets and scrolling stay aligned; retain viewport-bounded DOM and keyboard navigation.
- Bottom panels use a compact tab strip with active underline, diagnostic badge, keyboard switching and panel-specific actions. Problems rows are virtualized with severity, code and source position; selecting a row opens its source location. Keep progress states explicit, give an empty console a concise state description, and preserve the same workbench geometry while switching panels.
- Debug Console recognizes strict JSON objects/arrays, including prefixed, multiline and split stdout chunks. Render them collapsed with native details/summary disclosure, escaped keys/values and a copy-JSON action. Build children only on expansion, page wide collections in groups of 100, and limit depth to 80. Keep each retained log DOM node stable so later output preserves expansion and selection; follow output only when already at the bottom. Pending partial JSON has a short receiving preview, and malformed/truncated data remains text. Ordinary log output renders as escaped line spans. Each line carries a Web/Native source marker, level color (error, warning, success or debug), and token colors for URLs, source files and common log levels; pseudo-labels must not change `textContent` or the raw log contract. Keep at most 150 entries. Plain output retains the existing 64,000-character budget; streamed JSON may accumulate up to 2 Mi characters per entry with a 4 Mi-character total budget so large snapshots remain inspectable. Preserve clear/scroll behavior.
- File navigation has natural folder-first ordering, fuzzy path filtering, ancestor expansion, document reveal, collapse-all, arrow/Home/End/Enter navigation and ARIA tree metadata. The Explorer filter is hidden by default; Ctrl/Cmd+F reveals and focuses it only while Explorer has focus, retaining Monaco find in the editor. Escape from the filter or filtered tree, or the close icon, clears the filter, hides the widget and returns focus to the tree. Reset the widget on project replacement; Ctrl/Cmd+P remains independent. Ctrl/Cmd+P opens the floating Quick Open dialog with fuzzy paths, recent files, arrows/Enter/Escape and optional `:line:column`. It searches the shared index, debounces 60 ms and bounds results to 100 virtualized rows; no extra scanner or editor instance. Ctrl/Cmd+Shift+E opens Explorer, Ctrl/Cmd+Shift+F opens content search, Ctrl/Cmd+J toggles the bottom panel. Panel separators support pointer dragging, arrow keys and double-click reset.
- Explorer supports file/folder creation, native context menus, F2 rename, copy/cut/paste, relative path copy, OS reveal and Delete/Cmd+Backspace to system trash after confirmation. Internal drag/drop moves into folders or the root heading, expands hovered folders and scrolls near edges. Clipboard and drag payloads are project-local. New names reject traversal, hidden/generated/dependency paths and OS-reserved names; destinations never intentionally replace existing content. Copy uses exclusive writes, bounds walks to 20000 entries/10 levels and copy bytes to 1 GiB, rejects symlink/special-file trees and leaves partial destinations visible on failure. Moves validate then rename in the serialized worker; external filesystem changes can still race this preflight.
- Moving/renaming open documents updates tab document paths and language-provider request paths while retaining the same Monaco models, undo stacks and revision baselines. Model URIs have unique identities independent of current paths; discard asynchronous language results if a path changed. Deleted open buffers remain available and saves are blocked until the disk path is restored. File operations pause editor writes and defer watcher updates until tab remapping completes. Refresh the file index even when renaming a project manifest temporarily invalidates project configuration. These operations do not rewrite script imports or asset references, and filesystem undo/multi-selection/external drop import remain pending.
- Quick Open and file naming dialogs hide the embedded Web view and hide the Native surface like Settings. Restore prior focus only on cancellation; opening a result must keep focus in the new editor, and delayed modal close events must not steal it. `node packages/editor/electron/scripts/explorer-smoke.mjs` uses temporary files for shortcuts, dialog focus, creation, native menu callbacks, rename/undo/save, folder renames, clipboard, actual HTML drag/drop and cancelled/confirmed trash with dirty-buffer retention. It stubs native menu selection/dialog answers; file operations and system trash are real.
- Search fields use one group-owned focus border, with no nested input outline. Standalone Quick Open, asset, Git and Inspector search fields use a single border-color change rather than an extra outline. Keep keyboard focus visible on option buttons. The three fixed-width search toggles are case sensitivity, whole-word matching (boundary-marked `ab`, explicit accessible label/tooltip), and regex; whole-word passes ripgrep `--word-regexp` for both literal and regex searches, excluding matches within letters, digits and underscores. Do not implement a separate renderer regex engine.
- `project-service/search.ts` runs bundled `@vscode/ripgrep` as one cancellable child process outside the serialized project worker. Search is disk-only, limited to indexed editable paths, with literal/Rust-regex, case/word flags and comma-separated include/exclude globs. Use UTF-16 editor columns from ripgrep byte offsets, bounded snippets, 1000 matches, 8 MiB output and a 10-second budget. Cancel superseded searches and search on project switch/close; discard stale UI responses. Do not evaluate user regex on the renderer/main JS event loop.
- Assets Browser provides folder scope, recursive/path/type filters, name/size/modified sorting, virtual grid/list, metadata, bounded image previews, audio/video controls, source-tree reveal, relative path copying and OS reveal. Font/package/other entries currently have metadata/icons only. It does not unpack QPKs or replace the inspector's provenance/reference graph.
- Selected resources replace the bottom-right mode label with format and file size. Images also show original pixel dimensions and alpha-channel presence, with path/exact bytes/modified time in the tooltip. Read image headers on demand through the worker's Sharp metadata API using the same canonical/indexed access limits; account for EXIF orientation and animated frame height. Never report resized preview dimensions as source dimensions. Refresh on file change and clear on panel hide, deletion or project switch; discard stale asynchronous metadata.
- Panel resizing must keep overlapping virtual rows attached, including decoded thumbnails; do not move them through a DocumentFragment on each ResizeObserver event. Double-click image/audio/video cards opens a frameless large preview window with its own bounded media URL; Escape/close releases that window. Cache its webContents id before `closed`, and guard asynchronous loading against early close.
- Media URLs use session-scoped `qua-asset:` tokens and revalidate canonical root and indexed file access. Rasterize images (including SVG) in the project worker using Sharp, capped at 32 MiB/40 MP input, 160x120 thumbnails and 1280x900 previews. The UI queues at most four thumbnail loads; host cache is an LRU capped at 128 entries/8 MiB with duplicate requests coalesced. Audio/video stream with byte ranges; stop media and clear its source when the panel hides or selection/project changes. Reset tokens, cache and streams on project replacement/close. Never expose generic filesystem URLs or executable SVG/HTML documents to the workbench.
- Import uses the native file picker and a canonical existing destination folder, accepts media/font/package files only, and uses exclusive copies to avoid replacing existing files or following destination file symlinks. Refresh the shared project snapshot afterwards. Source assets remain authoring files, not live pushes into the game runtime. Rename/delete/move with reference rewriting, drag-and-drop import and import undo are still pending.
- Keep `@vscode/ripgrep` and `sharp` external in the Electron/worker build so binary resolution stays relative to their installed packages. Shipping installers must include the correct platform binaries; installed desktop distribution has not been validated yet.

## Local Git and change tree

- Git uses serialized, bounded child processes without a shell. Scope displayed paths to the opened project, preserve enclosing-repository safety checks for commits, and never silently commit staged files outside the project. Keep local branch/status in the bottom-left footer.
- Branch switching must not reject every dirty repository. Use normal `git switch` so non-conflicting index/worktree changes can carry across branches; Git must reject overwritten tracked/untracked files and unresolved conflicts. Do not use force checkout, discard, or automatic stash as a fallback.
- Unsaved editor documents are a normal user decision: native question offers save-all-and-switch, keep-drafts-and-switch, or cancel. Return structured `save-required` / `cancelled` / `blocked` results instead of throwing IPC exceptions for these cases. Save-all covers inactive tabs and propagates save conflicts. Keeping drafts preserves models and base revisions so subsequent external-change checks still guard saves.
- A checkout blocked by local changes is a readable warning in Source Control; true command failures may be errors, with transport prefixes removed. Do not show `Error invoking remote method` as product copy. Distinguish cancellation from failure and preserve the current branch/worktree after rejected checkout.
- `ui/src/workspace/git-tree.ts` derives conflict/staged/working-change groups with folder-first natural ordering, path-stable identities, original rename paths and M/A/D/R/U/conflict decorations. A file changed in both index and worktree appears in both groups. Tree/list mode is profile-local; fuzzy filtering reveals matching ancestors without erasing collapse state.
- Render changes with the shared virtual list, cache the tree when status is unchanged, retain selection across refreshes and support arrows/Home/End/Enter with ARIA tree metadata. Keep diff and stage/unstage bound to the full path and the correct group, never just the displayed basename. Refresh default clean/unavailable messages with status changes while retaining explicit operation warnings; normalize transport prefixes for every Git error entry point.
- `node packages/editor/electron/scripts/git-smoke.mjs` uses temporary repositories to verify real diff/stage/commit interactions, save/keep/cancel branch decisions, draft preservation when checkout changes the same disk file, blocked-checkout warnings, tree/list/filter and keyboard behavior, virtual DOM bounds and external Git refresh. Git status refresh is serialized and lightweight; the smoke explicitly tests external changes while the editor is not reporting native focus. Artifacts are in `.codex-tmp/editor-git-smoke/`; these tests must not alter the user's repository branches or commits.
- Source Control follows the compact VS Code shape: the branch action lives in the view toolbar beside small view/collapse/refresh icons; it must not occupy a separate full-width row. The commit message is one auto-growing field with a compact check action and `Mod/Ctrl+Enter`; keep the staged-only hint implicit in the disabled state and tooltip. The branch picker is an anchored two-row popover for switching or creating a branch.
- Git comparisons are separate readonly tabs in the shared document tab strip. A file tab remains the editable Monaco buffer; a worktree or staged diff tab has its own identity, can stay open beside other diff tabs, preserves the diff scroll/view state, and can be refreshed or reopened in the source file. Closing a diff never closes or replaces the document buffer. Diff tabs are bounded (12) and use one shared read-only Monaco diff editor.
- Git status refresh is lightweight and serialized; refresh while the editor is active and after focus/project changes. The Source Control view must remain correct when the host automation does not report native focus, so do not make external-change visibility depend solely on a focus bit.

## Preview boundary

- Only Web and Native are in scope. Default to one running session and release the previous backend before starting the next.
- The controller is authoritative only for editor lifecycle, not game state. Reject stale session traffic; cancellation, process exit, partial startup and teardown failure must be covered.
- Web runs the project's selected Web entry in a sandboxed WebContentsView without Node/preload privileges and with isolated temporary storage.
- Native runs the existing JavaScriptCore/Rust/wgpu product chain and embeds its actual native surface. Never introduce CPU/GPU image transport, shared pixel buffers, canvas drawing or screenshot polling as the display path.
- macOS uses `CAContext` + `CAMetalLayer` in Rust and an Electron main-process Node-API addon hosting `CALayerHost` in an `NSView`. Core Animation composes the native layer directly. This uses runtime-checked macOS SPI (also used by Chromium); unsupported platforms/hosts fail explicitly, with no image fallback. Windows/Linux native embedding remains unimplemented.
- `QUA_NATIVE_EDITOR_PREVIEW=1`, a per-session `QUA_NATIVE_EDITOR_TOKEN`, and the loopback control endpoint enable embedding. `/qua/preview` protocol v2 returns only a context id and viewport dimensions; there is no frame endpoint or pixel IPC. Native surface handles stay in Electron main, never the workbench/QPK.
- `PreviewPresentation` owns bounds, clipping, visibility and reparenting; the driver owns the layer lifetime and detaches it before stopping the process. Hide on modal/drag/hidden pane/minimize/error/reload and destroy on stop/failure. Rust retains the CAContext until its WGPU surface has dropped.

## Integrated terminal behavior

- The bottom Terminal panel uses lazy-loaded xterm.js/fit and real node-pty sessions in a separate lazy Electron utility process.
