## 打开生产打包

先保存所有改动并停掉正在运行的预览，再从标题栏应用菜单选择「文件 → 生产打包…」，或者直接按 `Ctrl/Cmd+Shift+B`（macOS 顶部系统菜单栏也有同一入口）。在弹窗里选中项目实际支持的目标，核对打包步骤后点击「开始打包」。

目前编辑器内置的打包对话框支持生成 Web 生产目录与 macOS Native `.app`。Cocos 和 Godot 请继续使用各自独立的平台命令行工具链（详见[平台指南](/docs/platforms)），它们不在这个弹窗的选项里；插件包项目也不使用游戏打包流程。

## 配置保存在项目里

游戏名称、`bundleId`、应用图标、Developer ID 代码签名以及 Apple 公证配置全部写在项目的 `qua.project.*` 文件中，不属于编辑器个人设置。签名证书和公证凭据请放在系统 Keychain 等安全位置，千万不要写进源码或配置文件。

详细配置字段与 CLI 用法见[Quack 生产构建配置](../../../../packages/build/quack/docs/production-build.md)。编辑器本质上是调用项目自有的 Quack 构建管线，不会另外拼装目标核心，也不会改写你的游戏引导入口。

## 查看进度与日志

打包面板会如实展示准备、资源打包、目标构建等阶段、资源包数量、完成/跳过/失败状态以及实际耗时。如果没有配置 Apple 公证，界面会明确标注该步骤已「跳过」——跳过不等于公证通过。

构建开始后，关掉弹窗也不会打断任务，它会在后台继续跑，重新打开还能接着看进度。构建日志默认折叠，遇到失败会自动展开并高亮关键信息（任务是否成功完全以构建协议返回的状态为准，不靠日志里有没有出现“成功”字样来判断）。

需要中途停止时请点击「取消」。取消或失败后，面板会保留完整日志和你的源码草稿，修好问题后重试即可；注意单纯关掉弹窗并不会取消构建。

## 检查产物

打包完成后可以通过「显示产物」定位到输出目录，在交付前至少核对以下几项：

| 产物类型 | 基本验证项 |
| --- | --- |
| Web | 用静态 HTTP 服务器启动生产目录，实际点一遍受影响的对白、选项、资源加载和存读档（开发预览正常不代表生产资源打包与 CSP 也正常） |
| macOS Native | 实际双击或命令行启动 `.app`，检查画面渲染、输入响应、音视频播放以及存读档跨重启是否正常 |
| 对外分发 | 另行核对安装包哈希、正式签名、Apple 公证票据、托管平台配置以及目标系统兼容性 |

需要记住的是，打出游戏包只是生成了本地成品，并不会自动帮你上传网站、提交商店、发布 GitHub Release 或者更新编辑器自己。关于编辑器自身的发版和更新机制，请看[获取编辑器](/docs/editor/downloads)。
