## 打开生产打包

先保存并停止预览，再从标题栏应用菜单选择「文件 → 生产打包…」，或按 Ctrl/Cmd+Shift+B。macOS 系统菜单栏提供同一入口。选择项目实际支持的目标，检查步骤后点击「开始打包」。

当前编辑器打包流程支持 Web 生产目录与 macOS Native `.app`。引擎另有 Cocos/Godot 构建能力，不代表它们已经成为这个对话框的目标选项；使用对应[平台工具链](/docs/platforms)。插件项目也不走游戏预览/打包流程。

## 配置由项目持有

游戏名称、标识、图标、Developer ID 签名与 Apple 公证设置放在 `qua.project.*`，不是编辑器主题或用户设置。凭据保留在 Keychain 等受支持位置，不要写进项目源文件。

详细配置与 CLI 说明见[Quack 生产构建](../../../../packages/build/quack/docs/production-build.md)。编辑器调用项目既有 Quack 构建链，不另造 target core 或修改游戏 bootstrap。

## 查看进度与日志

步骤列表显示准备、资源打包、目标构建等真实阶段、资源包计数、完成/跳过/失败状态及耗时。未配置的 Apple 公证会明确显示跳过；跳过不等于已公证。

关闭打包面板可让构建在后台继续，再次打开保留进度。日志默认折叠，失败自动展开；高亮帮助定位信息，完成状态来自构建协议，不是靠日志里的“成功”字样判断。

需要中止时使用「取消」。取消或失败后保留日志与草稿，修复根因再重试。不要只通过关闭对话框判断构建已经停止。

## 检查产物

完成后使用产物定位，确认版本、资源和入口来自本次构建：

| 产物 | 至少检查 |
| --- | --- |
| Web | 用 HTTP 服务启动生产目录，实际走完受影响对白、选择、资源加载与存读档；开发预览通过不能代替生产资源检查 |
| macOS Native | 实际启动 `.app`，检查渲染、输入、媒体、保存/重启；单看构建日志或 GPU 读回不能代替可见运行 |
| 对外分发 | 独立确认哈希、签名、公证、分发配置和目标系统验收 |

生成游戏产物不等于上传网站、发布商店、创建 GitHub Release 或发布编辑器本身。Editor 的 stable/beta 发行与更新见[获取编辑器](/docs/editor/downloads)。
