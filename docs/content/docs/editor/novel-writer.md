## 打开与配置

在左侧活动栏点击 Novel Writer 图标，整个编辑区域会切换成独立的写作工作区。点击资源管理器图标或按 `Ctrl/Cmd+Shift+E` 即可切回剧本工作区，两边各自未保存的草稿都会原封不动地保留。在写作工作区里，按 `Ctrl/Cmd+S` 保存当前稿件，按 `Ctrl/Cmd+,` 打开写作设置。

使用前请先配置 DeepSeek 模型；需要结合外部资料检索时再配置 Tavily。模型调用会消耗网络流量和提供商额度，发起任务前先核对一遍即将发送的项目设定和正文范围。Novel Writer 仅作为编辑器内的创作工具运行，不会作为游戏插件被打包进最终玩家端。

## 从项目或 QuaScript 建立任务

新建与当前项目关联的写作任务时，可以填写写作目标、篇幅、背景约束以及允许改动范围。项目里已有的世界观、人物设定和大纲会作为参考输入保留；缺失的设定可以通过「关联并补齐设定」由助手补充，不会偷偷覆盖掉你已经写好的内容。

顶部工具栏的「从 QS 改写」会读取当前 Monaco 编辑器里的正文或选区（包括尚未保存的内容），同时把文件路径、选区范围和版本快照存进任务里。如果回写前原 `.qs` 文件又在别处被改过，编辑器会提醒你重新取稿或先解决冲突。

即便预先导入了项目设定，后续的分阶段审核和大纲检查依然会完整执行。生成过程中看到的流式文本只是实时预览，最终结构化结果保存下来之后才算可操作的正式产出。

## 审核、重生成与回写

收到初稿后，可以先仔细通读一遍，补充修改意见或局部重生成某个阶段，再通过稿件和差异预览核对改动。回写项目时支持三种方式：新建 `.qs` 文件、追加到原文件末尾，或者智能替换原选区。智能回写会利用源码锚点与变量计划，尽可能保留原有的 TypeScript 代码、演出指令、选择分支与故事元数据，并在写回前跑一遍编译器静态诊断。

点击应用时，编辑器会再次校验项目身份、当前缓冲区、磁盘版本与改动范围。最终写回的结果是一份可撤销的 Monaco 草稿，按正常流程保存后才会落盘并更新索引与预览，不会直接篡改运行中的游戏状态；如果新建了场景文件，记得回到项目入口里把新场景接上去。

需要注意，脚本通过编译只能说明语法没问题，并不能保证人物动机、叙事节奏或每条运行分支都合情合理。回写之后请亲自读一遍正文，并在预览里把受影响的选项、跳转和读档测试跑通。

## 保存、继续与回收站

写作任务的默认数据目录为 `~/.quaengine/novel-writer`（若配置了应用数据根目录则会跟随覆盖），工作流通过追加式 JSONL 日志和快照实现断点恢复。隐藏写作视图并不会中断正在进行的生成；关闭编辑器时也会保护未保存稿件与运行中任务，已保存的阶段产物和检查点在下次打开后可以接着继续。

普通删除会把任务放进应用内置的回收站，随时可以找回；「重置任务」则会清空生成产物与历史记录、只保留最初的基础输入，操作前请确认清楚。不要为了重置任务而直接去手动删数据目录。

## 导出归档

导出的 ZIP 归档包含 `README.md`、`project.json`、`manifest.json`、`combined.md` 以及 `artifacts/` 下的 Markdown 与 JSON 文件。导出范围包括状态为 `approved` 和 `draft` 的产物，会排除 `needs_review` 和 `rejected`——**需要注意，随包导出的草稿并不代表已经通过审核**。

归档里不会导出原始工具调用日志和模型 API 密钥，但项目元数据、需求简报和故事正文依然可能包含未公开的敏感设定，对外分享前请先检查压缩包内容。此外，这个 ZIP 仅用于带出稿件，并不是完整的事件日志、凭据或运行环境备份。
