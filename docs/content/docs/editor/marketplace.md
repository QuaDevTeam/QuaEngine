## 插件能提供什么

扩展包通过在 `package.json` 的 `quajs.extension`（schema 1）中声明 `runtime`、`devtools` 或同时声明两者来接入。其中 `runtime` 提供游戏运行期功能，`devtools` 提供编辑器面板或项目索引器——注意把包安装进项目依赖，并不等于已经把它的 runtime 自动接进游戏引擎里。

内置的角色和动画工具随编辑器一起提供。如果是安装第三方插件，请自行评估它的代码行为与权限范围：Registry 的静态规则检查和可选的 AI 审查能帮忙筛掉常见风险，但它们既不是安全沙箱，也不能对恶意代码做绝对担保。

## 安装与启停

1. 打开游戏项目，在左侧活动栏点击「插件」进入插件市场（它是一个普通的停靠视图，不会遮挡侧栏和文档）。
2. 安装前先核对包名、精确版本号、能力类型、来源以及审查状态。
3. 编辑器会按项目原本的 npm/pnpm 工作流安装锁定的精确版本，并默认禁用包的安装生命周期脚本（使用 Yarn 的项目请通过自己的 Yarn 流程安装）。
4. 安装后检查依赖变动和 devtools 启用状态；如果是 runtime 插件，别忘了按插件文档到游戏入口里注册。启停编辑器内的 devtools 面板不会去改写你的剧本文本。

市场里的目录与「官方」徽章由 Registry 服务端白名单核发，包名带 `@quajs` 前缀或者自定义的 JSON 目录都不能自封官方；即便通过自定义目录发现的插件，安装时依然要过所选 Registry 的版本审核。如果在安装中途点取消，记得检查一下 `package.json` 和锁文件，包管理器可能已经写入了部分改动。

## 发布自己的插件

在编辑器里直接打开你的插件包目录（不需要游戏配置），通过菜单「插件 → 发布」用 GitHub 登录 Registry。生成所有权声明（claim）后，检查并保存 `package.json` 里的更新草稿。

接着构建插件，点击「打包并检查文件」仔细核对即将发布的 tarball 名称、版本号、文件列表和 SHA-512 哈希，确认无误后再将这份一模一样的归档发布到 npm。npm 登录全程留在你的本机环境，Registry 不会接触你的 npm token，输入的一次性验证码（OTP）也只在内存里用于这一次发布操作。

发布到 npm 的 `latest` 稳定标签后，即可回编辑器提交给 Registry 登记。所有权 claim 有效期为 24 小时，在首次成功登记后就会消耗（之后的日常版本更新不需要重复登记）；如果发的是带 `next` 标签的预发布版，需要等提升为 `latest` 稳定版再提交。每次改完包清单都要重新打包；万一在发布的最后关头点取消，有可能 npm 那边其实已经接收成功，重试前先去 npm 确认一下实际状态。

## 审查与故障处理

如果包因为触发规则被隐藏了，请根据界面提示的原因修复问题、发一个新版本号，服务端会自动复审。普通的后续升级不用再走登记流程，不过一旦 npm 维护者列表发生变化，可能需要重新发一次带新 claim 的版本来证明权限。如果遇到登录失败，请排查操作系统的安全存储（Keychain / Credential Manager）、Registry 地址和网络环境，编辑器不会降级用明文保存凭据。

完整的包所有权、自动审查、同步与部署契约见 [Registry 服务参考](/docs/editor/registry)，编辑器插件开发接口见[编辑器插件契约](../../../../docs/design/editor-plugins.md)。另外，游戏运行期动态下发剧情依然走 Runtime QPK 和引擎激活流程，插件市场解决的是开发期包管理，不能替代运行时的包信任校验与状态迁移。
