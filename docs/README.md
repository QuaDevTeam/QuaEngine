# QuaEngine documentation

The project website and creator handbook, built with **svedocs 0.2.4** and Svelte 5. The site owns its landing page, navigation, reading layout, brand artwork, and light/dark theme; svedocs owns content compilation, routing, search, code tools, metadata, and agent endpoints.

## Run

Use Node.js **22.12+** (latest Node 22 LTS recommended) and pnpm **12.3.4**. This directory is an independent pnpm workspace: no engine, Electron, or Rust build is required.

```bash
pnpm --dir docs install --frozen-lockfile
pnpm docs:dev
pnpm docs:check
pnpm --dir docs test:markdown
pnpm docs:build
pnpm --dir docs preview
# With preview running, and Chrome or Playwright Chromium available:
pnpm --dir docs test:smoke
pnpm --dir docs test:editor
```

The local server uses `http://127.0.0.1:4173`. Browser QA artifacts are written to the ignored `docs/.generated/qa/` directory. Use `DOCS_TEST_URL` to point the smoke test at another preview, or `CHROME_PATH` to select a browser executable.

Restart the preview process after rebuilding: its loaded client manifest must match the new static output. Run `pnpm --dir docs test:sidebar` against the same preview to check previous/next, history and mobile navigation.

## Content

- `content/docs/`: Chinese tutorials and section landing pages; `content/docs/en/` contains the English handbook entry, quick start, first-scene tutorial and complete Editor section.
- `content/pages/`: site home and brand downloads.
- `design/`, `guides/`, `security/`, `reviews/`: preserved source documents at their original repository paths.
- `scripts/prepare-content.mjs`: imports package READMEs and existing documents, adds metadata/provenance, rewrites repository links, and copies selected brand exports.
- `.generated/content/`: disposable svedocs input, regenerated by dev/check/build. Do not edit it.
- `src/lib/theme/`: custom Svelte components and theme CSS.

QuaScript fences (`qs` / `quascript`) are highlighted at build time through the supported rehype hook using Shiki and the repository's VS Code TextMate grammar, including embedded TypeScript. The grammar is consumed directly; no engine or editor package build is required. Other unsupported DSLs keep plain text and accessible copy controls. Markdown tables retain native column layout inside a separate keyboard-scrollable container.

This is an intentional partial English rollout: creator guides outside onboarding and Editor remain Chinese, and links from English pages identify that language. Keep root Chinese routes stable and mirror translated paths below `docs/en/`. The theme uses svedocs locale routing, scoped search, and its language selector; missing translations remain disabled in that selector. Editor has 14 matching routes per language, combining workflow pages with localized package references. `test:editor` checks route pairs, internal anchors, prerendered language/alternates, scoped search, switching, and desktop/mobile light/dark layouts. Add translations at their original content source, never by altering DOM text for a screenshot.

References preserve the source language and evidence limits. Historical reviews remain labeled as historical. Every generated page links back to its original file on GitHub. Add new packages to the source list rather than maintaining a second copy of their README.

## Static hosting

`pnpm docs:build` produces **`docs/build/`**, including all documentation routes, local search chunks, sitemap, robots, Markdown twins, `llms.txt`, and `llms-full.txt`. Upload the complete directory. Configure directory `index.html` resolution and serve `404.html` for missing routes with status 404. No server-side API keys or search service are required.

The production origin is **https://quaengine.com**. `wrangler.jsonc` deploys the static directory as the `quaengine-docs` Worker in the project Cloudflare account, with an exact custom domain for the apex. It uses directory-index HTML handling and a real 404 fallback, not an SPA fallback. Hashed application assets receive immutable caching through `static/_headers`.

## Deploy with Wrangler

After authenticating Wrangler with the project account, run:

```bash
# Validate and build without publishing:
pnpm docs:check
pnpm docs:build
pnpm --dir docs deploy:check

# Exercise Cloudflare's actual asset routing locally:
pnpm --dir docs dev:worker
# In another terminal:
DOCS_TEST_URL=http://127.0.0.1:4176 pnpm --dir docs test:smoke

# Recheck, rebuild, and publish the custom domain:
DOCS_SITE_URL=https://quaengine.com pnpm --dir docs run deploy
# Verify the published site:
DOCS_TEST_URL=https://quaengine.com pnpm --dir docs test:smoke
```

Wrangler is pinned in this workspace. Use the existing Cloudflare authentication; no application secrets or bindings are required. The exact domain route leaves `registry.quaengine.com` and other subdomains independent. The deployment command does not commit or push repository changes.

`DOCS_SITE_URL` controls canonical metadata at build time and must match the production domain when publishing. Only static mode is supported by this project configuration. Deployment records can be inspected with `pnpm --dir docs exec wrangler deployments list`.

`.github/workflows/docs.yml` validates the docs independently and uploads the static artifact. Production deployment is performed explicitly through Wrangler, not on every CI run.

## Dependencies and brand

Keep `svedocs` and `svedocs-cli` on matching versions. The local workspace preserves `trustPolicy: no-downgrade`; it overrides svelte-check's Chokidar 4 dependency to the API-compatible Chokidar 5 watcher because registry policy rejects the older version. Chokidar 5 and Vite 8 require a modern Node runtime.

The canonical artwork and prompts live in [`../assets/brand`](../assets/brand/README.md). The content preparation script copies selected exports into `static/brand/`. Do not edit those generated copies. Site assets omit WIP labels while the capability pages describe actual implementation and validation limits.
