# Demo 开发约定

本 demo 尚未公开发布，是内部技术与内容演示。**不承担旧代码、旧接口、旧剧情或旧存档的向后兼容要求，允许直接做 breaking changes。** 不为旧版增加迁移、兼容别名、双实现、存档版本分流或兼容性审批，也不为了保留旧步骤编号限制剧本写作。

按当前获批的故事和技术设计直接重构、替换或删除 demo 内容，同步更新调用方、文档和相关测试。需要时可以重置 demo 开发测试数据。验证当前版本的存读档、分支和运行正确性，不测试跨版本恢复。

详细规范见 [.agents/development-rules.md](.agents/development-rules.md)。本约定覆盖 demo 旧档案或 skill 中相反的兼容要求；引擎与渲染边界、QPK 资源体系和当前版本的质量要求仍按仓库规范执行。用户已于2026-09-08要求恢复图片生成并补齐缺失美术，此指令覆盖此前暂停要求。按 `.agents/art-production.json` 与 imagegen 技能执行；名字、既定服装和常规美术取舍无需再次审批。

## 叙述视角（2026-09-09 更新）

玩家代入神代凛，故事采用以凛为信息中心的第三人称限知叙述。无署名旁白使用“凛”“她”或明确的人物姓名；角色对白、电话、录音和消息按各自立场使用第一人称。叙述人不是凛，不将无署名独白中的“我”当作默认写法。

旁白可以写凛当时的感受、记忆、猜测，但要与已证实事实分清；不突然进入其他人的内心，也不跳去凛无从得知的现场。两位女性同场时，动作换主语要及时点明姓名，不能让连续的“她”指向不同人。笑、愣住、犹豫都要给出可理解的动作和前因后果，避免“自己先撑不住”一类没有说完的表达。

第三人称文字与镜头构图是两件事。凛可以按需要被写出外在动作，也可以在合适构图中出场；不因台词署名自动显示立绘，不为这次改写机械添加人物。现有逐场演出保持作者明确指定，远程说话者仍不当作在场人物。

这一规则覆盖历史档案、skill与旧测试中的“凛第一人称”及据此禁止凛出场的要求，不影响角色身份、时间线、广播规则和既有素材的可用性。
