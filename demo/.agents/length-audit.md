# 正文篇幅核查与扩写标准

当前统计以 [QS 实施状态](manuscript-status.md) 和 [机器快照](manuscript-count.json) 为准：完整结局90,205—90,288字，提前交接71,034—71,110字。旧风险分支已删除。

以下为扩写前的历史审计，保留当时约2.09万字的基线与统计口径；不是当前完成量。

## 扩写前结论

**该版篇幅不足以完成本项目约定的中长篇体验。** 已有从相遇到结局的完整事件链，但仍是压缩首稿。完整结局一遍约 2.09 万汉字，只达到 9 万字目标下限的约 23%。九个章节入口、三个结局和浏览器通关验证都不能证明篇幅达标。

本页保留历史核查口径；当前统计由脚本实时生成，已包含跨夜揭露、独立停机与提前交接。分场规划仍是目标，不把预算算入已完成正文。人物口吻精修也不能替代场景展开。

## 统计口径与结果

在仓库根目录运行 `python3 demo/scripts/story-length.py` 可重算。只统计 U+4E00—U+9FFF 汉字，不计标点、空白、拉丁字母和数字；因此这不是文字处理软件的混合字符数，也不是日文译稿字数。正文口径排除代码、装饰器、角色姓名标签、选项按钮和章节标题；保留正文中的告示与短信内容。

工具针对当前 QS 写法解析 `scope.response` / `scope.pick` 的字符串分支，遇到其他插值会报错。它不是通用 QS 解释器；改动运行分支或脚本语法时须同步复核工具。当前路线按 `prologue-state.ts` 核对：短结局在第五章分离，跳过独立检查及后续章节；两种安全结局共享后半主线。六组选项形成 48 种可达组合，每个结局 16 种；短结局不计未到达的第六组选项。

| 口径 | 汉字数 |
| --- | ---: |
| 全部 QS 源文件，含标签、元数据及互斥文本 | 24,056 |
| 全部正文，共同段只计一次，互斥回应分别计入 | 22,437 |
| 单次完整结局「明天，请再一次呼唤我」 | 20,908—20,962 |
| 单次普通结局「雨后的来信」 | 20,937—20,991 |
| 单次短结局「未完成的交接」 | 16,091—16,145 |

两种安全结局只在材料保全与调查后续处有少量不同，不能宣传为三条中长篇路线。全部正文与一遍完整路线之间只有约 1,500 字的差额，也不能据此许诺大量二周目内容。

原文档中的 6—8 小时是制作目标，尚未实测成立。仅作算术示例：按每分钟 250—400 个汉字，当前完整路线纯阅读约 52—84 分钟，不包含点击、思考、打字速度和未来音画演出；这不是玩家时长预测。不能通过放慢打字、添加强制等待或重复已读内容补足中长篇时长。

相对 96,000 字路线预算，仍缺约 **7.5 万字正文**。短结局及额外回应另计，不承担填补完整路线缺口的任务。

## 扩写与验收

1. 先逐场细化第一至三章，让规则通过观察与反证建立，让双方在危险前已有多次主动选择相处。再展开第四至六章的核验、冲突与合作，最后完成第七章和尾声；序章补写只处理具体衔接。
2. 每场有时间、地点、凛当下想做的事、对方的不同意愿或现实阻碍，以及离场时实际发生的变化。新增段落若只是换词重复设备说明、夸赞对方、反复喝茶收伞，删掉或重写。
3. 感情依 `relationship-arc.md` 的日期与动机：Mara 不替凛解释全部心理，凛不突然善于长篇表白。和好需要持续的信息共享与选择权，告白前已有独立于救援的吸引和邀约。
4. 世界规则及证据按 `mystery-logic.md` / `timeline.md` 逐场检查。禁止为了悬念让角色漏报险情、无资质入站、凭录音直接定罪，或新增临时超能力解围。
5. 最终完整路线正文以 **9—11 万汉字**为篇幅验收范围，逐章工作预算为 9.6 万；先写完整场景再核算，不按比例机械拉长每句。达到字数仍须通读检查场景变化、对白口吻、关系递进和线索可理解性。
6. 扩写可直接增删执行步骤与重构旧代码；demo未发布，不做旧存档兼容、迁移或版本分流。之后再做 QS 编译及三结局、存读档、章节重读回归。
7. 完整稿和演出就绪后，以不跳读、正常设置的游玩记录评估时长。未完成前，状态继续标明“压缩首稿，待扩写”，不对外标称已经达到中长篇或 6—8 小时。
