# 资产制作流程

旧故事专用生成器与其自动重生旧素材的 npm 命令已经移除。当前仅保留 `assets:build` 打包入口；新的 `assets:generate` 不应在没有新资产定义时伪装可用。

首批机器清单与提示词已建立在 `prologue-art.json`。用户已要求图片后续统一制作，当前主动暂停生成，不再等待或请求 API／CLI 选择。全部图片仍为 planned；当前开发只推进剧本与 UI。

## 下一次制作顺序

1. 依据 characters.md 与 prompt-bible.md 做凛、Mara 的常服参考，再做四位配角。名字与服装无需重新请用户批准。
2. 先完成序章必需的街道、播音室、资料室，再根据分镜扩展天气变体。
3. 从已确定的参考派生差分，逐张检查脸、发型、手、服装和透明边缘；不得用新设定外的自动风格替换角色。
4. 写入机器可读资产清单，保存模型、参数、来源与实际文件状态；按当时可调用的工具实现生成器。不要把旧模型、个人机器绝对路径或旧预算当作当前要求。
5. 图像、配乐、环境声、可选配音先独立审核，再加入资产包；密钥不写入项目。中间图、失败图和工具缓存留在忽略目录，不混入发布资产。
6. 用现有 Quack 主包构建静态故事素材。以后若制作运行期增量内容，遵循 Runtime QPK 流程，不加入单资源直推通道。

## 当前工程命令

```sh
pnpm --filter demo assets:build
pnpm --filter demo typecheck
pnpm --filter demo build
```

这些命令验证运行壳与资源打包，不表示新故事或新美术已经完成。
