# 2026-09-12 文学、画面与演出修订

本轮实际修改全部14份QS，补入14张图片：8张叙事特写、6张空间背景。保留三结局、既定日期、固定24小时返回和文件不变规则。当前是面向关键段落的编辑与演出修订，不等于九万字全稿已经通过最终文学验收。

## 先查资料，再确定写法

- [UCD《Revising and Editing Fiction》](https://www.ucd.ie/teaching/t4media/revising_and_editing_fiction.pdf)：先检查人物目标、冲突和结构，再修句子；动作、环境与潜台词能够承接对白，仍须警惕无关动作和过度修饰。本稿据此削减人物反复解释自己感受的句子，保留有因果的反应。
- [《Ever17》打越钢太郎／中泽工导演访谈](https://lemniscatranslations.wordpress.com/ever17-15th-anniversary-uchikoshi-nakazawa-interview-part-1-non-spoiler/)：受访创作者把剧本、图像规格、角色差分、声音、脚本实现和实际游玩检查放在同一制作流程里，也谈到为消除图文矛盾而返修。它是创作者访谈的英文整理，并非所有Galgame的统一规范。本轮据此从具体剧情列出需要看的物件，再确定美术请求与切换位置。
- [《428》石井二郎谈ADV结构](https://news.denfaminicogamer.jp/kikakuthetower/indiesgame_fest_mv_01/2)：讨论分支、玩家知识和角色间行动影响，以及用时间段控制复杂结构。本作的应用是保留已有信息阶梯和选择后果，不为增加“游戏感”临时添轮回或新谜底。
- [Ren'Py官方演出文档](https://www.renpy.org/doc/html/transitions.html)：转场可以承接图像、场景的变化，也提供叠化和移动等不同表达。这里参考的是演出组织，实际实现仍使用QuaScript现有背景、角色与动画装饰器。

以下是针对本稿作出的编辑判断，不是上述资料的引文：日常应让人产生想继续相处的理由；异常改变原有日常的意义；冲突落实到一次具体的隐瞒；共同面对风险之后，也要允许关系慢慢修复。叙述跟随凛，画面负责空间与物件，立绘负责人物反应，文字留下声音、触感和她未能说出口的话。

## 改了什么

| 段落 | 文学处理 | 画面／演出 |
| --- | --- | --- |
| 接站、委托 | 用受损样本和空着的作品申请交代凛为何来到青叶；面包交接表现Mara的照顾 | 雨中入场、共伞靠近、纸袋特写、归途空间 |
| 生日留言 | 通过长短版本的听感让人物发现停顿的意义，减少抽象评语 | 旧磁带工作台作为待修物件；明确生日留言来自旧卡；Mara靠近试听 |
| 首次返回 | 当面的人没有开口，耳机里的声音却在继续；保留疑问 | 注意力先在人物，接收结束才切监听设备，避免表头状态与正在接收相反 |
| 铜铃与蓝伞 | 从实物对照中产生理解，不抢先替读者解谜 | 箱底铜片、两伞并排；看完物件再恢复人物 |
| 洗衣店、海边、灯塔 | 修正笑点衔接；简图、书和未发出的邀约保留余味 | 靠近滚筒、坐回长凳、接球换位、衣装不串场 |
| 碎音、隐瞒、揭露 | 用空白便签、缩小的窗口、没写下的分机号承接惶恐 | 电话结束收回电话姿势；隐瞒后拉开距离，早晨读全文时坐下 |
| 调查 | 保留核查必要条件，减去重复主题解释 | 礼子仍在场接受追问；春香从门边发问；Mara离开桌旁再回来 |
| 十九点十二分 | 安全通知与人的紧张分开写，用等候和动作表现余悸 | 饮料放稳后握手特写，拥抱前回到人物 |
| 补休、游船、咖啡厅 | 没有工作理由也愿意一起出门；闲谈服务于关系变化 | 药妆店、船舱、甲板看青叶、共享桌面；布丁开始吃之前结束静物特写 |
| 告白、尾声、交接结局 | 保留明确表白；用普通见面、做饭和下一次约定收束 | 近景、起坐、厨房换位、东京雨街与回程车窗；远程声音不自动出场 |

具体例子：原文“凛有些怀疑，刚才是不是只听见了自己的呼吸”之后还用一段旧经历解释。现在改为她屏住气、继续听见摩擦声、圈出那一秒而留空；读者和凛一起判断声音的来源。

原灯塔对白用“因为饭团真的吃掉了”解释为什么喜欢开放结尾，前后难以接上。现在凛说门已经打开，认为那个人总能说出口；Mara提醒她开门的是另一个人。两人的阅读分歧也让眼前未说出的邀请有了余味。

本轮新增33段时间轴动画和6处入场调用，包含共伞靠近、侧身让路、坐起、后退、离席及回座。动作依赖剧情落点，不逐句重复套用。

## 图片与成本范围

[完整提示词与生成记录](narrative-direction-assets.json)保存模型、quality、参考图、prediction ID、退回原因、实际路径与SHA-256。[图片预览](narrative-direction-preview.html)直接读取项目中的交付图。

使用本地Replicate CLI的 `openai/gpt-image-2.5-flare`，全部 `medium`、2048×1152 WebP。17次请求交付14张；3次定向修正分别处理铜铃形状、蓝伞红线位置、东京街景误带UI。没有调用high。

8张特写位于 `demo/assets/images/inserts/`；6张背景位于 `demo/assets/images/backgrounds/`。总新增图像约4.48MB，沿用静态Quack QPK加载。没有新建松散资源推送接口。

复核原生截图时还发现：`CharacterExit` 会提交透明度0，单独 `ShowCharacter` 只恢复在场标记。已在四处重新出场时补 `CharacterEnter`，避免人物实际透明；回归会同时核对CSS透明度和场上角色。

17处原有 `ClearBackground()` 均改为具体空间或连续持有的正确背景。本轮另外修复了若干段内地点变更仍显示上一地点的问题。空白背景归零不代表每个叙述动作都已有专用CG；未补的重点构图仍包括完整双人拥抱、接吻、灯塔小画近景以及更完整的声音演出。
