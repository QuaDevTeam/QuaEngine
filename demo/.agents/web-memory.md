# Web 图片与字节资源内存

2026-09-09。用户要求实际约束 Web renderer 和 Web QuaAssets 的内存。本次落实以下修改。

## 已实现

- **生产字节存储**：demo通过`createWebAssetStorage`创建共享IndexedDB存储，供读取素材的QuaAssets与engine assets使用。删除整包常驻`MemoryAssetStorage`方案。`cacheSize`表示持久存储清理阈值，不代表JS内存上限；仍须容纳挂载包，不能误删唯一资源源。
- **按索引读取**：IndexedDB增加`lookupKeys`多值索引，覆盖规范名、完整path与各级路径后缀。每次切表情只反序列化匹配素材，不在JS里扫描并解码所有人物字节。新增索引会为已有资源缓存补建查询键；不改存档或剧情状态。
- **写入与统计**：QPK入库按最多8MiB一批写入（单个超大素材单独写），减少IndexedDB批量结构化克隆峰值。统计与清理只读取数值索引键，不会为计算大小反序列化图片字节。
- **并发读取**：renderer每个QuaAssets最多4个读取并行。同一身份／类型／名字／包候选／修订的未完成请求共享读取；已失效且尚未开始的请求跳过。底层已开始的AssetStorage读取不能强制中断，但其结果不会绑定到过期节点。
- **闲置资源预算**：对象URL引用归零后最多等待250ms，闲置URL同时受16个和32MiB估算预算约束，超过立即回收。估算为文件字节＋已知图片宽×高×4；当前仍有使用者的URL不会被驱逐。渲染器可用`getWebAssetMemoryStats(assets)`读取活动／闲置URL、估算字节、活动／排队读取数。
- **卸载与失败**：`revoke()`使未完成的旧加载失效；替换资源失败会释放旧URL，避免在包卸载后无限保留旧图。DOM unmount清空层节点和根节点，句柄释放会移除src引用。动态包是否可以卸载仍由engine判断；渲染器预算只处理临时资源。

## 内存边界

32MiB只限制闲置URL估算，不是整页、WebGL/GPU或浏览器图片缓存的硬上限。可见资源、字体、音视频、浏览器解码缓存需要额外内存；revoke后由浏览器决定何时真正回收。没有尺寸元数据时只能计入已知文件字节，不能假装知道解码开销。

首次QPK下载和解析仍会在内存中持有完整压缩包及解包字节，8MiB写入批次不能消除这一峰值。很大的产品包应进一步按章节拆为Quack QPK，并按engine生命周期挂载／卸载；本轮没有引入HTTP range解析、流式解包或擅自卸载运行中的包。无需为了显示一张图片挂载全套解码对象，也不要全游戏预热图片。

## 验证

单元回归覆盖：同资源并发合并、revoke中止投影、4请求并发限制、过期排队任务丢弃、按解码尺寸限制闲置预算、活跃图片不驱逐、250ms最终回收，以及IndexedDB持久读取、路径别名索引、8MiB分批写入、数值索引清理和统计、旧缓存索引补建。实际生产QPK阅读与资源生命周期计数另见本轮验收记录，不能把之前内存存储版本的回归当作本实现的验证。
