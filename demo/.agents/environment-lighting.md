## 已接入的渲染

背景插件的 `characterLighting` 参数随背景写入引擎投影，保存为普通叙事呈现数据。渲染器只读取参数，不根据图片文件名、对白、章节或当前时间猜灯光。清除背景或换到不带参数的背景，人物恢复原色；转场期间使用目标场景的参数，当前不插值光照。

```qs
@SetBackground('backgrounds/laundromat-evening-anime-v2.webp', {
  characterLighting: {
    ambient: [1.02, 0.98, 0.92],
    shade: { color: [0.90, 0.94, 1], from: [0.2, 0], to: [0.8, 1] }
  },
  transition: { type: 'crossfade', duration: 320 }
})
```

`ambient`是sRGB三通道倍率。`shade`从白色渐变到指定倍率，`from/to`使用人物图框的0—1坐标，不是屏幕像素。渐变表示画面中的大范围受光变化，不是根据人体法线算出的体积光。

Web使用SVG颜色矩阵与渐变相乘，最后只应用一次原始人物alpha。这样不会给透明区域上色，也不会把发丝的半透明边缘重复相乘。效果作用在整个人物合成结果上，脸部差分和身体使用同一套参数。没有模糊眼睛、改动PNG、生成发光外圈或给人物加一圈投影。

实现位于 `@quajs/renderer-web/plugins/character`，Vue仅把共享SVG描述转成VNode；React/Svelte使用Web的DOM插件时复用同一路径。背景插件负责复制参数与转场，引擎负责快照隔离。没有新事件总线、逐帧游戏状态推断或额外素材推送通道。

本轮在14个背景指令上明确配置了四类场景：洗衣房、雨天商店街、夜间资料室、夜间监听室。其他场景保留原色，需逐场审阅后再配光。Native/Cocos目前继续按原色显示人物，本轮不宣称跨平台光照一致；原生仅检查共享QS编译。

## 技巧选择

| 方法 | 本项目用途 | 本轮状态 |
| --- | --- | --- |
| 环境色与宽范围明暗渐变 | 将白色衣服、皮肤和头发放进同一色温中，保留赛璐璐细节 | 已实现并按四类环境配置 |
| 人物alpha蒙版着色 | 把光照限制在人形内，保留软发丝 | 已实现，复用合成人物的alpha |
| 手绘局部光照蒙版 | 窗框光斑、伞下阴影、脸部保护区 | 后续可选；需对应动作的专用蒙版与QPK来源，不宜所有差分套一张 |
| 脚底接触阴影 | 全身远景，让鞋底落在地面 | 暂未添加；当前大多数立绘脚部在画面外，不能在腰下随便画黑椭圆 |
| 深度图遮挡与视差 | 栏杆、桌沿遮挡人物，少量镜头移动 | 可做重点CG试验；需要一致的前后景分层、深度与相机关系 |
| 法线图着色 | 少数明确移动的光源改变人物亮面 | 需要逐姿势绘制／审核法线；把alpha当高度会出现充气浮雕，不采用 |
| SSAO／环境光遮蔽 | 可信深度场景的局部接触与凹陷遮蔽 | 不应用于现有纯2D画面；单张AI深度不能证明接触关系，容易在脸部和轮廓制造脏边 |

建议先完成逐场环境色，再挑一张有栏杆／桌沿的重点画面制作分层遮挡。只有需要光源移动时才投入法线图；深度、法线、遮挡图均属于可选QPK素材，不为每一张表情立绘默认增加全尺寸纹理。

## 内存与边界

本轮不额外读取人物PNG，不缓存着色后的位图，不创建新的Blob URL，不驻留Canvas/WebGL纹理或帧循环。每个当前人物的滤镜定义随DOM创建／移除，渐变由小段内联SVG描述；中性参数不创建滤镜。原有QuaAssets读取、对象URL引用计数与卸载逻辑继续负责PNG。

SVG滤镜仍有浏览器/GPU临时合成开销。以640×1280、RGBA8的单张表面估算是3.125MiB，方向着色可能涉及数张表面；实际尺寸、复用、格式与DPR由浏览器决定，不能把它算进原来32MiB的闲置URL预算，也不能宣称整页内存恒定。暂不加模糊、全屏后处理、深度图或多层阴影缓冲；若需最低开销，场景可只写ambient，走单个颜色矩阵。

首次QPK仍需下载／解析整个包并写入IndexedDB，本轮未改成流式或按章节加载。系统Chrome验收出现本地资源请求 `ERR_ADDRESS_INVALID` 和启动等待超时，改用已安装的测试版Chromium153后，冷启动与多次刷新读档已通过；这只是换浏览器后的观察，不宣称已查明网络错误根因。失败诊断单独保留，不将它归因于尚未显示的人物滤镜。
