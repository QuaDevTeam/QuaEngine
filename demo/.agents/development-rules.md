# Demo 开发规范

2026-09-08，用户明确规定：demo 从未公开发布，不需要考虑 breaking changes，也不承担对旧版玩家进度的兼容责任。

## 直接以当前设计为准

- 可直接重写或删除旧代码、剧本、接口、选择、节点、目录结构与测试夹具。过去的实现不是新设计的约束。
- 不保留旧实现、旧别名或双路径；不为旧存档写迁移，不按稿次新增数据库或存档命名空间，不为了兼容固定步骤编号。
- 不为 breaking change 请求批准，不添加“影响已有玩家”的警告或发布迁移流程。既有授权内直接做完重构。
- 开发测试数据可以重置。历史创作记录可作为参考，但其中的版本兼容要求已失效。

## 仍需完成的工作

新版本自身的分支、存读档、续读、章节选择和当前数据状态必须正确；测试随新设计更新，不要求恢复旧稿位置。剧情要有可理解的因果、人物动机与实际正文，不能把移除兼容负担当作降低内容质量或缩减已承诺范围的理由。

逻辑状态由引擎／store管理，渲染器只投影并通过pipeline发意图。内容使用既有QS和QPK构建路径。修改限于任务范围，不回滚仓库中其他工作的改动。

正文按最新 `narrative-foundation.md` 与 `scene-plan.md` 落地。已有稿件可以保留确实适用的段落，也可整章替换；目录与模块数量服从新稿组织，不为旧14文件结构设置限制。

本页与 `demo/AGENTS.md` 覆盖旧交接记录、分场文档及demo skill中关于存档迁移、版本隔离和保留旧步骤的要求。

## 叙述视角（2026-09-09 更新）

玩家代入神代凛，故事采用以凛为信息中心的第三人称限知叙述。无署名旁白使用“凛”“她”或明确的人物姓名；角色对白、电话、录音和消息按各自立场使用第一人称。叙述人不是凛，不将无署名独白中的“我”当作默认写法。

旁白可以写凛当时的感受、记忆、猜测，但要与已证实事实分清；不突然进入其他人的内心，也不跳去凛无从得知的现场。两位女性同场时，动作换主语要及时点明姓名，不能让连续的“她”指向不同人。笑、愣住、犹豫都要给出可理解的动作和前因后果，避免“自己先撑不住”一类没有说完的表达。

第三人称文字与镜头构图是两件事。凛可以按需要被写出外在动作，也可以在合适构图中出场；不因台词署名自动显示立绘，不为这次改写机械添加人物。现有逐场演出保持作者明确指定，远程说话者仍不当作在场人物。

这一规则覆盖历史档案、skill与旧测试中的“凛第一人称”及据此禁止凛出场的要求，不影响角色身份、时间线、广播规则和既有素材的可用性。
